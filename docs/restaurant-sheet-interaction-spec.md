# 식당 지도 시트 — 상호작용 합격 기준

지도 하단 식당 목록 시트(`features/restaurant/components/RestaurantListSheet.tsx`)의 **감각**에 대한
합격선이다. 보고된 증상("터치가 잘 안 먹히고, 너무 올렸다 내렸다, 스크롤이 답답하다")을 고칠 때
"좋아졌다"로 판정하지 않기 위해 먼저 못을 박았다.

## 이 문서의 전제 — **마우스로 재면 전부 통과한다**

사용자의 결정적 제보: *"마우스로는 기존에도 잘되는 것처럼 보였고, 실제 프로덕션에서 손으로 쓸 때
문제가 많았다."*

시뮬레이터의 마우스 탭은 **이동이 정확히 0pt** 이고 즉시 release 된다. 실제 손가락은 탭 한 번에
3–20pt 를 구르고, 플릭 속도는 1,000–4,000pt/s 다. 이 화면의 결함은 **전부 그 차이에 숨어 있었다** —
개발 중에는 한 번도 밟지 않는 경로에.

그래서 아래 기준은 전부 **손가락을 흉내 낸 입력**(이동이 있는 `touch_path`, 실제 속도의 플릭)으로
검증한다. 무이동 탭으로만 확인한 항목은 검증한 것이 아니다.

---

## A. 탭이 먹는다 (터치 확실성)

| ID | 기준 | 개선 전 | 개선 후 |
| -- | ---- | ------- | ------- |
| A1 | 손가락이 몇 pt 굴러도 카드 탭이 열린다 | ✗ **4pt 만 흔들려도 무반응**(실측) | ✓ 4pt 흔든 탭 열림 (iOS·안드 실측) |
| A2 | 스크롤 직후에 바로 눌러도 열린다 | ✗ 250ms 사각지대(`SCROLL_GUARD_MS`) | ✓ 창 자체를 삭제 |
| A3 | 세로로 스크롤만 하고 손을 뗀 것은 탭이 아니다 | ✓ (임계값의 대가로) | ✓ 네이티브가 press 를 취소 |
| A4 | 마커·빈 지도·모달 딤 탭이 카드 상세를 열지 않는다 | ✓ (400ms 창으로) | ✓ 배달 경로 자체가 없어짐 |
| A5 | 지도를 팬한 직후에도 카드 탭이 먹는다 | ✗ 400ms 사각지대 | ✓ 창 삭제 |
| A6 | 어떤 순서로 만져도 목록이 영구히 안 눌리는 상태가 없다 | ✗ `draggingRef` 가 true 로 남을 수 있었다 | ✓ 플래그 자체가 없어짐 |
| A7 | 카드 가운데를 누르면 상세로 간다(주소 토글이 가로채지 않는다) | ✗ 카드 높이의 ~30% 가 주소 토글 | ✓ hitSlop 12→6 (32pt 로 축소) |

**진짜 원인(실측 2026-08-17):** 8px 좌표 판정이 아니라 **gorhom 콘텐츠 팬에 활성화 임계값이 없다는
것**이었다. 2–4pt 만 움직여도 `Gesture.Pan` 이 활성화되어 RNGH 중재가 카드의 press 를 **취소**한다.
마우스는 이동 0pt 라 이 경로를 절대 밟지 않는다. `activeOffsetY={[-10,10]}` 하나가 A1 을 뒤집었다.

## B. 시트를 잡을 수 있다 (팬)

| ID | 기준 | 상태 |
| -- | ---- | ---- |
| B1 | 움직일 수 있는 면 = 핸들 + 칩 줄 + 목록 전체 | ✓ 유지 |
| B2 | 핸들 블록 ≥ 40pt | ✗ **의도적으로 안 함**(32pt). 접힘 높이가 그만큼 지도를 먹고, 콘텐츠 팬이 켜져 있어 접힘에서도 ~95pt 전체가 손잡이다 |
| B3 | 목록이 맨 위일 때 아래로 끌면 시트가 내려간다 | ✓ |
| B4 | ~~세로 드래그에 임계값 없이 즉시 반응~~ → **10pt 뒤에 시작한다** | 기준을 **고쳤다**. "임계값 0" 과 "작은 흔들림이 탭을 죽이지 않는다" 는 동시에 성립할 수 없다. 10 은 iOS 스크롤뷰(≈10pt)·안드 `touchSlop`(8dp)이 쓰는 값이다. 임계값을 넘는 순간의 10pt 점프는 `sheetGestureHandlers` 가 보정한다 |
| B5 | 가로 스트립·칩 줄에서 가로로 끌면 시트는 가만히 있다 | ✓ `activeOffsetY` 가 세로 이동으로만 활성화를 허용해 더 확실해졌다 |

## C. 예측 가능하게 움직인다 (스냅)

| ID | 기준 | 개선 전 | 개선 후 |
| -- | ---- | ------- | ------- |
| C1 | 손가락이 간 곳보다 더 가지 않는다 | ✗ **전체에서 180pt 튕겼는데 중간을 건너뛰고 접힘까지**(실측) | ✓ 같은 플릭이 중간에서 멈춤 (iOS 실측) |
| C2 | 짧은 플릭도 한 칸은 움직인다 | ✗ 185pt(간격의 절반) 못 넘기면 제자리 | ✓ **30pt** 플릭으로 접힘→중간 (iOS·안드 실측) |
| C3 | 스냅 애니메이션이 300ms 안에 끝나고 두 플랫폼이 같다 | ✗ iOS 과감쇠 스프링 / 안드 250ms timing(속도 버림) | ✓ `duration 280 · dampingRatio 1` 로 통일 |
| C4 | 중간에서 목록을 위로 끌면 전체로 올라가고 **같은 제스처로** 스크롤이 이어진다 | ✓ (라이브러리 동작) | ✓ 유지 |
| C5 | 앱이 스스로 옮기는 경우가 사용자와 싸우지 않는다 | ✗ 지도를 만지면(**두 손가락만 얹어도**) 무조건 접힘까지 · 네트워크 오류를 0건으로 읽고 스스로 올라옴 | ✓ 한 칸만 내림 · 오류는 0건이 아님 |

**남긴 것:** 중간 스냅에서는 목록이 스크롤되지 않는다. gorhom 은 **가장 높은 스냅에서만** 스크롤을
푼다(`useScrollable`). 이건 설정으로 못 바꾸고, 중간 스냅은 "마커를 눌러 카드 한 장을 보는 자리"
라서 그 제약이 오히려 맞다. 목록을 읽으려면 한 칸 더 올리면 되고, 그 한 칸이 이제 30pt 플릭이면 된다.

## E. 결과가 **적거나 없을 때** (2026-08-17 추가)

지금까지의 기준은 전부 강남(카드 20장) 기준이었다. 결과가 0건·1건·소수일 때는 **다른 코드
경로**를 타고, 실제로 여기에 가장 나쁜 결함이 있었다.

| ID | 기준 | 개선 전 | 개선 후 |
| -- | ---- | ------- | ------- |
| E1 | 목록이 짧아져도(0·1·소수) 시트를 콘텐츠에서 끌어 내릴 수 있다 | ✗ **펼침에서 시트가 얼어붙는다**(핸들로만 내려감, iOS·안드 실측) | ✓ 양쪽 실측 통과 |
| E2 | 빈 지역이 **연속**될 때도 매 검색마다 이유를 보여 준다 | ✗ 첫 빈 지역에만. 이후엔 빈 지도 + 접힌 시트 + 침묵 | ✓ 검색이 끝날 때마다 설명 |
| E3 | 접힘에서 0건이 되면 시트가 중간까지 올라와 이유와 CTA 를 보여 준다 | ✓ | ✓ (실측: 문구·CTA 모두 보임) |
| E4 | 실패를 0건으로 착각해 시트가 스스로 올라오지 않는다 | ✗ | ✓ |
| E5 | 안내 문구가 늘고 줄어도 카메라 예측 캐시가 통째로 날아가지 않는다 | ✗ `.clear()` | ✓ 접힘 관측만 무효화 |
| E6 | 0건 설명을 들고 있는 동안에는 지도를 만져도 **접힘까지 내려가지 않는다** | ✗ 핀치(두 손가락)만으로도 설명이 사라짐 | ✓ 중간이 바닥 (실측) |
| E7 | 자동으로 올라온 중간 스냅에서 빈 상태 **CTA 가 잘리지 않는다** | ✗ 874pt+안내 2줄 ≈17pt, 667pt 는 안내 없이도 ≈11pt 잘림 | ✓ 빈 상태 위 여백 32→8 (실측) |
| E8 | 0건인데 스켈레톤 카드가 빈 상태 위에 얹히지 않는다 | ✗ 마커 선택 + 0건이면 겹침 | ✓ 이끌 카드가 없으면 안 그림 |
| E9 | 0건 사이에 네트워크 실패가 껴도 내려 둔 시트가 저절로 안 올라온다 | ✗ 실패가 `wasEmptyRef` 를 풀었다 | ✓ 실패면 판정 자체를 건너뜀 |

**E1 의 정체 (라이브러리 결함).** gorhom 은 스크롤 오프셋을 **드래그 이벤트에서만** 갱신한다.
목록이 줄어들면 스크롤뷰가 손가락 없이 오프셋을 0 으로 되감으므로 그 이벤트가 오지 않고,
시트는 "아직 1,500px 스크롤돼 있다" 고 믿는다. 최상단 스냅에서는 그 값이 드래그 변위에서
통째로 차감되어 **시트가 못 박힌다**. `sheetScrollHandlers.ts` 가 값을 실제와 맞춘다.

### 아직 안 고친 것 (보고만)

- **빈 상태 CTA·푸터 행이 RN 코어 `Pressable`** 이다(`V2Button`·`V2ListRow`). 0건 화면에서는
  그것들이 손가락이 닿는 **유일한 면**이라, 카드에서 걷어낸 유령 press 가 여기 남아 있다는
  지적이 감사에서 나왔다.
  **그런데 iOS 실기기에서 두 번(40pt·18pt 플릭) 정밀하게 노렸는데 재현되지 않았다** —
  시트가 한 칸 움직이는 동안 `필터 초기화` 는 불리지 않았다. 이유는 gorhom 의 팬이
  RNGH 기본값인 `cancelsTouchesInView` 를 그대로 두어 **iOS 터치가 취소되기** 때문이다
  (RNGH `Pressable` 은 자기 제스처에만 그것을 끈다). 카드에서 났던 옛 사고는 스크롤뷰의
  `Gesture.Native()` 경로였고 성질이 다르다.
  → **미확인 위험**으로 남긴다. 안드로이드는 취소 전달이 다를 수 있어 확인이 필요하고,
  고치려면 디자인 시스템 두 컴포넌트를 손대야 해 **앱 전역에 영향**이다.
- **빈 상태 CTA 높이 38pt**(`V2Button size="m"`). 같은 디자인 시스템이 최소 터치 타겟을
  44 로 규정하고 "hit-slop 으로 확보 권장" 이라 적어 두었다. 0건 화면의 유일한 버튼이다.
- **중간 스냅에서 푸터가 안 보이고 스크롤도 안 된다.** 0건일 때 `저장한 곳 보기`·
  `식당 알려주기` 는 시트를 100% 까지 올려야 닿는다(iOS 기준 5pt 만 보인다).
- **0건에서 필터를 바꾸면 로딩 없이 CTA 가 손가락 밑에서 바뀐다.** 왕복 내내 이전 빈 상태가
  그대로 있다가 다른 라벨의 버튼으로 교체된다(`useRestaurantList` 가 `isPlaceholderData` 를
  안 내보낸다). 두 번째 탭이 엉뚱한 행동이 될 수 있다.
- **드래그 도중 0건 자동 상승이 발사되면** 손 뗀 자리(스냅 아닌 높이)에 시트가 멈출 수 있다는
  지적. 팬 중에는 프로그램 스냅을 미루면 되지만 shared value 배선이 필요해 남겼다.
- **`지도 넓혀서 다시 찾기` 가 몇 번 누르면 아무 일도 안 한다**(`widenLevel` 상한). 0건
  화면의 유일한 행동인데 반응이 없는 상태가 생긴다.
- **결과가 1건이면 지도에 `1` 배지(클러스터)로 그려진다** — 한 곳을 보려고 배지를 눌러
  재검색을 기다려야 한다. 서버 클러스터링 임계값 문제라 앱만으로는 못 고친다.

## 검증 방법 (재현용)

두 시뮬레이터에서 같은 입력을 돌린다. **마우스 클릭(무이동)으로는 아무것도 증명되지 않는다.**

1. 4pt 흔든 탭 → 상세가 열려야 한다
2. 접힘에서 30pt 플릭 → 중간까지 올라와야 한다
3. 전체에서 180pt·3,000pt/s 플릭 다운 → **중간에서 멈춰야 한다**(접힘까지 가면 회귀)
4. 전체에서 목록 스크롤 → 상세가 열리지 않고 시트가 내려가지 않아야 한다
5. 지도를 팬 → 한 칸만 내려가야 한다

희소·0건은 별도로 돈다:

6. 목록을 스크롤 → 0건 필터(`음식 종류 = 샐러드`) → 펼침에서 **빈 영역을 끌어내린다**
   → 시트가 따라와야 한다(안 움직이면 E1 회귀)
7. 0건 상태에서 지도를 팬 → `현재 지도에서 찾기` → **매번** 이유가 떠야 한다(E2 회귀)

## 이 문서를 고치는 규칙

기준을 못 맞추면 **코드를 고치고**, 기준 자체가 틀렸다고 판단되면 **왜 틀렸는지 함께 적어** 고친다
(B4 가 그 예다). 기준을 조용히 지우지 않는다.

## F. 버튼 위에서 시작한 손가락 (2026-09-12 추가)

제보: "버튼 영역은 스와이프해도 시트가 닫히거나 열리지 않는다." 시트 안의 눌리는 것 중 **RN 코어
`Pressable`**(JS 리스폰더)로 만든 것들 — 필터 칩(`SelectableChip`), 카드 주소 토글(`AddressBlock`),
빈 상태 CTA(`V2EmptyState`→`V2Button`), 실패 재시도(`V2ErrorState`), 푸터 행(`V2ListRow`) — 은
gorhom 콘텐츠 팬(RNGH)과 **중재되지 않는다.** 카드(RNGH `Pressable`)와 결과 헤더 버튼은 이미 갈렸다.

| ID | 기준 | 조치 |
| -- | ---- | ---- |
| F1 | 칩·CTA·행 위에서 세로로 10pt 넘게 움직이면 시트 팬이 이기고 press 는 취소된다 | `SelectableChip`·`AddressBlock` 을 RNGH `Pressable` 로. `V2Button`/`V2ListRow`/`V2EmptyState`/`V2ErrorState` 에 `gestureHandler` opt-in(시트 안에서만 켠다 — RN Modal 안에서는 RNGH 가 안드로이드에서 죽으므로 전역 전환 금지) |
| F2 | 같은 자리에서 10pt 안에 떼면 탭이다 | `activeOffsetY` 임계값 그대로(B4) |
| F3 | 칩 위에서 가로로 끌면 레일이 스크롤되고 시트는 가만히 있다 | RNGH `ScrollView`(B5) 그대로 |

회귀: `tests/restaurantSheetTouchables.test.ts` 가 시트 안 터치 파일에 RN 코어 Pressable import 가
없는지, 디자인 시스템 버튼/행이 RNGH 경로를 갖는지 본다.
