# 신신당부 UX 라이팅 가이드

신신당부의 문구는 서비스를 설명하는 글이 아니다. 사용자가 지금 무엇을
보고 있는지 이해하고, 다음 행동을 결정하도록 돕는 인터페이스다.

참고 원칙:

- [토스, 좋은 에러 메시지를 만드는 6가지 원칙](https://toss.tech/article/21021)
- `humanize-korean` v2.0.0의 번역투·피동·명사화 점검 기준

## 기본 목소리

- 본문과 안내는 자연스러운 해요체를 쓴다.
- 제목은 짧은 질문이나 현재 상황으로 쓴다.
- 버튼은 누른 뒤 일어나는 일을 행동형으로 쓴다.
- 사용자를 탓하거나 겁주지 않는다.
- `사용자`, `이용자`, `고객님`보다 문장에서 주어를 자연스럽게 생략한다.
- `서비스`, `시스템`, `서버`, `API`, `토큰`, `처리`처럼 구현을 설명하는
  말은 화면에 내보내지 않는다.

## 상태별 규칙

### 로딩

기다리는 대상이 분명할 때만 문구를 쓴다.

- `로딩 중...` → `건강 기록을 불러오고 있어요`
- `분석이 진행됩니다` → `식단을 살펴보고 있어요`

### 빈 화면

없다는 사실로 끝내지 말고, 첫 행동으로 얻는 이점을 알려 준다.

- `데이터가 없습니다` → `아직 기록이 없어요`
- `등록된 식단이 없습니다` → `첫 식사를 기록하면 오늘 섭취량을 볼 수 있어요`

### 완료

서비스가 무엇을 처리했는지보다 사용자가 얻은 결과를 말한다.

- `성공적으로 저장되었습니다` → `검사 결과를 저장했어요`
- `문의가 등록되었습니다` → `문의를 보냈어요`

### 오류

가능한 범위에서 아래 세 가지를 순서대로 쓴다.

1. 지금 어떤 상태인지
2. 왜 그런지
3. 여기서 무엇을 하면 되는지

원인을 모르면 추측하지 않는다. `다시 시도해 주세요`가 실제 해결책일 때만
쓰고, 버튼은 `다시 불러오기`, `사진 다시 선택`, `로그인하기`처럼 구체적으로
쓴다.

- `서버 오류가 발생했습니다` → `지금은 연결이 원활하지 않아요. 잠시 후 다시 해 주세요.`
- `파일 업로드 실패` → `사진을 올리지 못했어요. 인터넷 연결을 확인한 뒤 다시 올려 주세요.`
- `인증 토큰이 유효하지 않습니다` → `로그인 시간이 지났어요. 다시 로그인해 주세요.`

`HTTP 500`, 오류 코드, 요청 경로, 원본 예외 메시지는 사용자 문구에 포함하지
않는다.

### 권한

기술 이름보다 허용했을 때 할 수 있는 일을 먼저 말한다.

- `카메라 접근 권한이 필요합니다` → `음식 사진으로 식단을 기록하려면 카메라 접근을 허용해 주세요.`

`설정에서 허용해 주세요`라고 안내하면 같은 오류 화면에 `설정 열기` 버튼과
실제 설정 이동 동작을 함께 제공한다.

### 되돌릴 수 없는 행동

제목은 결정할 행동, 설명은 실제 결과를 쓴다.

- 제목: `이 기록을 삭제할까요?`
- 설명: `삭제하면 다시 볼 수 없어요.`
- 버튼: `삭제` / `취소`

## 건강 정보

- 수치, 단위, CKD 단계, 검사명, 고유명사는 임의로 바꾸지 않는다.
- `안심`, `정상`, `안전`처럼 의학적 확신을 주는 말은 근거가 있을 때만 쓴다.
- 섭취 상한을 `권장량`, `목표`, `남은 양`처럼 채워야 하는 값으로 표현하지
  않는다.
- 진단·처방을 대신하지 않는다는 고지는 유지하되, 필요한 경우
  `담당 의료진과 상의해 주세요`처럼 다음 행동을 함께 쓴다.
- 알림은 수분 제한 등 개인별 지침과 충돌할 수 있는 일괄 명령을 피한다.

### 행동 주체와 책임

- 화면이 실제로 하지 않는 전화, 의료진 전달, 모니터링, 알림을 약속하지 않는다.
- 연락이 필요하면 `의료진에게 직접 연락해 주세요`처럼 누가 행동하는지 쓴다.
- `판단은 의료진의 몫`, `알리는 것까지가 우리 몫`처럼 책임을 나누거나
  서비스가 한 일을 자랑하지 않는다.
- `안전해요`, `먹어도 괜찮아요`, `문제없어요`, `적합해요`처럼 의료적
  허용으로 읽히는 말 대신 `개인 참고 기준 안`, `기준보다 500mg 많음`처럼
  확인된 사실을 쓴다.
- 앱이 계산한 참고 범위와 검진기관 판정, 의료진이 정한 개인 목표를 구분한다.
- 상태·원인·긴급도는 승인된 임상 규칙에서 받은 값만 옮긴다. 문장을 더
  단호하게 보이게 하려고 모델이나 템플릿이 긴급도를 보태지 않는다.
- 자동 생성문은 프롬프트 규칙만 믿지 않는다. 화면에 보내기 전 책임 분할,
  거짓 동작 약속, 근거 없는 안전 단정을 검사하고 안전한 결정론 문구로
  대체한다.

## 근거가 필요한 문구

- 법률 본문과 약관은 자연스럽게 보이도록 축약하지 않는다. 원문을 유지하고
  법무 확인을 거친다.
- 법률 본문과 실제 동의·보관·파기 흐름이 다르면 문구만 고치지 않는다.
  배포 전 법무·제품·개발 책임자가 정책과 구현을 함께 맞춘다.
- `암호화해서 안전하게 보호`, `정부 가이드라인 준수`, `모든 권고가 공인
자료 기반`, `새 자료를 바로 반영` 같은 보장은 구현 기록과 책임자 확인이
  있을 때만 쓴다.
- 동적으로 받은 정책·공지 문구도 화면에 나오기 전 같은 기준으로 관리한다.

## 표현 점검

다음 표현은 그대로 쓰지 않는다.

| 피할 표현                        | 권장 방향                                     |
| -------------------------------- | --------------------------------------------- |
| 오류가 발생했습니다              | 구체적인 실패 대상 + 다음 행동                |
| 성공적으로 처리되었습니다        | 사용자가 얻은 결과                            |
| 데이터를 불러옵니다              | 실제 대상: 기록, 검사 결과, 식단              |
| 서비스를 이용할 수 있습니다      | 사용자가 할 수 있는 행동                      |
| ~에 대해 / ~를 통해 / ~에 있어서 | 목적어와 동사를 직접 연결                     |
| 진행됩니다 / 제공됩니다          | 능동형 또는 사용자 결과                       |
| 입력해주세요                     | `입력해 주세요` 또는 더 구체적인 필드 행동    |
| 다시 시도                        | `다시 불러오기`, `다시 저장하기` 등 구체 행동 |

## 구현 계약

- `V2ErrorState`에는 상황을 설명하는 `title`을 반드시 넘긴다.
- 재시도 버튼을 쓰면 `retryLabel`도 반드시 넘긴다.
- 오류·빈 상태에서 특정 행동을 안내하면 같은 화면에 실제로 동작하는 CTA를
  둔다.
- API 원본 메시지는 `getErrorMessage` 경계를 거친 뒤 화면에 표시한다.
- `npm run audit:ux-copy`로 한국어 문자열과 OS 권한·i18n·식당 JSON 문구를
  함께 점검한다.
- 법률 문구, 수치, 단위, 날짜, 직접 인용은 자동 윤문 대상에서 제외한다.
