# 앱 전체 회색 면 점검 — 2026-09-07

약 복용 화면에서 입력·선택·안내 영역에 깊은 회색 `surface`가 사용되고 있었다. 다른 건강 기록 페이지의 `surfaceSunken`과 역할이 달라 보이는 원인이었다. 전체 기능의 같은 용도를 찾아 기존 공통 토큰으로 수정했다.

## 기준

| 역할 | 적용 기준 |
| --- | --- |
| 입력, 선택지, 보조 버튼, 안내, 빈 화면 | 기존 `surfaceSunken` — 라이트 `#f8f8f8`, 다크 `#39393e` |
| 기존 깊은 회색 | `surface` — 라이트 `#eaeaec`, 다크 `#3f3f45`; 데이터 트랙·미디어 등의 구분이 필요한 곳에 유지 |
| 화면 바닥과 카드 | `bed`, `canvas`, `card`의 기존 층 유지 |
| 선택과 누름 | 선택 테두리·체크, `surfacePressed` 유지 |
| 작은 안내 글자 | 다크의 옅은 회색 면 위에서 기존 불투명 글자 토큰을 사용하는 `surfaceBodyText` / `textOnSurface` |

팔레트 자체의 색상 값이나 글자 크기, 간격을 전역 변경하지 않았다. 기능 데이터, 저장, 알림 시간, 권한 로직도 변경하지 않았다.

## 소스 점검 범위

`app`, `src/features`, 공통 컴포넌트의 surface/fill 및 직접 지정한 회색을 검색하고 역할을 검토했다. 22개 기능 디렉터리는 [목록](feature-inventory.json), 수정한 75개 코드·검사 파일은 [변경 목록](changed-surfaces.json)에 기록했다. 파일 수는 화면 수가 아니다.

| 영역 | 확인 및 수정 |
| --- | --- |
| 약 복용 | 기록·관리·추가·검색·직접 입력·사진 대체 화면, 제품 카드·시간대·알림·선택지 |
| 홈·건강 기록·식사 | 여섯 기록 페이지의 공통 비활성 버튼, 텍스트 식사 입력, 기록 방법·레시피 가져오기, 기존 시트 보조 영역, 식사 분석의 다크 면 |
| 가입·온보딩 | 입력, 성별·다중 선택, 약관, 비활성 진행 버튼 |
| 내 정보·설정 | 공통 이름·닉네임·비밀번호·전화번호 입력, 프로필 선택, 건강 배지, 의료 참고자료 검색·배지 |
| 커뮤니티·레시피 | 검색·댓글·답글 맥락·멘션·투표·신고, 스토리 사진 자리·갤러리·한마디, 레시피 작성·재료·태그·조리 단계·인원·안내·등록 버튼 |
| 식사·통계 리포트 | 설명·결론·캡션·중립 배지·기간 선택·이동·재시도 버튼 |
| 기능 안내 | 안내 시트 아이콘 배경 |
| 식당·상담·구독 | 이미 용도별 `fill.control`, `fill.normal`, `fill.alternative`를 사용하는 부분 확인. 면의 역할을 유지 |
| 건강 검사·의료 데이터·공지·정책 등 | 전용 health theme의 떠 있는 면, 카드와 바닥, 기존 공통 컴포넌트 사용 확인 |
| analytics·food·food-analysis·nutrition | 화면 없는 데이터 모듈까지 목록에 포함 |

유지한 회색은 그래프의 미사용 구간·트랙, 프로필/실제 사진 로딩 자리, 지도와 목록의 구조적 바닥, 선택·눌림 피드백이다. 작은 삭제 아이콘처럼 입력 면과 구분되어야 하는 표식도 유지했다. `colors.fill.normal`은 흰 면에서 약 `#f4f4f5`로 합성되어 이번 깊은 회색 결함과 다르다.

## 시뮬레이터 확인

iPhone 17 Pro / iOS 26.5, 기존 로컬 TEST 앱과 Metro 8085에서 확인했다.

- 약 복용: 입력, 선택 시간대와 알림, 추가 방법, 검색과 키보드, 사진 기능 대체 화면, 빈 기록, 빈 관리 화면을 확인했다.
- 라이트·다크: 약 복용과 붓기 페이지를 비교했다. 레시피 작성과 스토리 빈 화면도 두 모드에서 확인했다.
- 공통 입력: 설정의 닉네임 화면을 열어 라이트 면을 확인했다.
- 테스트 기록은 저장하지 않았다. 선택한 복용 시간대를 해제하고 알림을 끈 상태로 나왔으며, 최종 화면은 라이트 모드의 빈 약 추가 페이지다.

알림 다크 캡처는 배경 교체 후, 작은 글자 대비를 마지막으로 보정하기 전에 촬영했다. 그 글자 대비는 최종 자동 검사로 검증했다. 약 검색 후보·실제 사진 인식 결과·약이 등록된 관리/기록 화면은 데이터나 연동이 없어 이번에는 소스 경로를 확인했다. 가입·통계 등 모든 화면을 시뮬레이터에서 직접 순회한 것은 아니다.

## 검증

- TypeScript 전체 검사 통과.
- 변경 파일 ESLint: 오류 0개, 경고 72개. 경고가 없는 상태라고 주장하지 않는다. 상세는 [로그](checks/lint.log).
- 공통 면·대비·입력·글자 크기·커뮤니티·레시피·설정 등 회귀 검사: 11개 스위트, 272개 검사 통과. [로그](checks/regression.log)
- 약 복용·알림 시간·건강 기록 대비 검사도 [GATES.md](GATES.md)의 명령을 최종 재실행해 통과했다. 검증 항목 6개 충족, 미충족 0개, 포기 0개.
- 기존 `lightContrastAudit`에는 구현 구조와 맞지 않는 소스 문자열 검사 5건이 있다. 변경 전 파일을 읽도록 연결한 기준 실행과 변경 후 실행 모두 같은 5건 실패, 55건 통과였다. 선택 칩의 문자열, 분리된 커뮤니티 라우트, 회색 바닥 화면 수, 분리된 내 정보 헤더를 가정하는 검사들이다. [변경 전](checks/legacy-audit-before.log), [변경 후](checks/legacy-audit.log)
- 설정 입력이 반드시 깊은 회색이어야 한다던 검사 1건은 새 공통 기준에 맞게 수정했고, 깊은 회색 탐지기 자체는 독립적인 양성 대조군으로 유지했다.

전체 앱의 모든 상태를 실기기에서 확인했다는 의미는 아니다. 소스 전수 점검과 대표 화면의 실제 렌더링 검증을 구분한다.
