## 공통 디자인

- 흰 페이지, 기존 v2 중성 표면, 짙은 글자. 브랜드 오렌지는 저장과 입력 포커스·복약 체크에 사용한다.
- 가로 여백 20pt, 4pt 간격 체계, 제목 28pt, 섹션 17pt, 선택지·본문 15pt, 보조 설명 13pt.
- 수치 입력은 Pretendard SemiBold를 명시한다. 기존 네이티브 숫자 입력의 시스템 폰트와 혼용되지 않는다.
- 체중·혈당은 44pt 수치, 혈압 두 칸은 36pt. 라벨과 단위는 값 입력 후에도 보인다.
- 선택 항목은 중성 바탕 + 진한 테두리로 구분한다. 오렌지 틴트의 큰 선택 바탕을 쓰지 않는다.
- 여섯 페이지의 상단 바에 선택 날짜를 표시한다. 본문은 큰 기록 제목과 한 줄 설명으로 시작한다. 정보 버튼 터치 영역과 저장 상태도 공통이다.
- 키보드 이동은 네이티브 키보드의 Reanimated 값을 따라간다. 푸터 패딩을 키보드 이벤트마다 바꿔 레이아웃을 다시 만들지 않는다.
- 수위·추가 행·눌림 반응은 기존 Reduce Motion 설정을 존중한다. 화면 진입에 항목별 시차를 주지 않는다.

## 기능 경계

- 약 복용을 독립 페이지로 추가했다. `POST /medications/intakes`의 기존 날짜·scheduleId 계약으로 1회 기록하며, 확인 응답의 taken/planned로 화면 수치를 갱신한다.
- 복약 저장 중 중복 입력을 막고, 실패하면 선택 상태를 유지한다. 미저장 선택은 공통 이탈 확인으로 보호한다.
- 수분은 빠른 추가와 직접 입력을 모두 지원한다. 추가는 로컬 상태이고 저장할 때만 합계를 보낸다.
- 혈압·혈당의 측정 맥락과 임상 수치 범위, 체중 변화 계산, 부기 부위별 관찰값은 기존 계약을 유지한다.
- 실기기 데이터로 오인될 테스트 건강 기록은 저장하지 않는다. 저장 성공·실패·중복 호출은 서비스 경계를 대체한 테스트로 검증한다.

## 검증 기록

iPhone 17 Pro / iOS 26.5의 기존 테스트 세션에서 확인했다. 신규 서버 실행·네이티브 빌드·배포는 하지 않았다.

- 수분: 빠른 추가 100mL → 합계·시각·저장 문구 반영. 뒤로가기 → 계속 기록하기 → 입력 유지. 다시 뒤로가기 → 저장하지 않고 나가기 → 홈 복귀. 확인창 문구 잘림과 관찰 가능한 중복 빈 팝업 없음. 첫 추가 내역이 하단 페이드에 닿는 것을 보고 요약 그림 높이와 목록 위 간격을 줄였다. 최종 화면에서 첫 행과 시각·삭제 버튼이 온전히 보이며, 행 삭제 후 합계가 0으로 돌아오는 것도 확인했다.
- 혈압: 두 값의 라벨·단위와 선택 상태, 숫자 키보드, 내리기 버튼, 하단 저장 버튼의 복귀 확인. 사용자가 제보한 최저혈압 80의 상단 잘림을 실제 재현했다. 높이 조정만으로는 해결되지 않아 기본 플레이스홀더를 터치를 통과시키는 별도 텍스트로 교체하고 공통 입력 프레임 높이를 명시했다. 예시 120/80, 실제 임시 입력 88/108, 다시 비웠을 때를 확인했다.
- 혈당: 임시 숫자 입력 후 저장 활성화. 공복·식후 변경 시 값 유지, 해당하지 않는 조건은 제자리를 유지한 채 비활성화. 테스트 값은 지우고 종료했다. 상단 중복 정보가 마지막 선택지를 밀어내는 것을 보고 날짜를 상단 바로 옮겼다. 공통 플레이스홀더 수정 후 44pt 예시 100이 온전히 보이며, 아래 기록 영역까지 드래그 스크롤되는 것도 확인했다.
- 체중: 저장된 수치 초기 표시, kg 단위, 어제와 비교, 최근 7일 표와 저장 버튼 확인.
- 약 복용: 홈 타일 → 독립 페이지. 선택 전 저장 비활성, 체크 후 활성, 해제 후 원복. 최종 날짜·요약 수치·작은 캡슐 그림·안내·저장 버튼 배치도 확인했다. 실제 복약 기록은 보내지 않았다.
- 부기: 홈 타일 → 독립 페이지. 발목 → 살짝 부었어요 → 자국이 남아요 선택 후 얼굴로 전환했다가 발목으로 돌아오면 선택값이 유지된다. 선택 전후 주요 컨트롤의 위치가 유지되고, 마지막 자국 선택지와 저장 버튼이 보인다. 뒤로가기 확인창의 두 문구도 온전히 표시되며, 테스트 초안은 폐기 후 홈으로 복귀했다.

자동 체크는 GATES.md의 실행 기록을 따른다. 복약의 성공·실패·중복 입력은 실제 서비스 함수를 호출하되 네트워크 경계를 대체한 테스트로 확인한다. 건강 기록과 통계 화면 이름 연결을 포함한 9개 테스트 묶음 85건이 통과했다. 추가한 약 복용 라우트에 맞게 기존의 고정 라우트 수 기대값도 갱신했다. 공통 숫자 입력칸 최종 수정 이후 TypeScript와 ESLint, 모든 실행형 검증 항목을 다시 통과했다. 최종 검증 항목은 완료 7개, 미완료 0개, 제외 0개다.

문구 감사는 새 문구의 교정 후보가 없었다. 프로젝트 전체에서는 기존 후보 12건이 남아 있다. 건강 관련 변경 경로의 ESLint는 오류 0개, 기존 RecordView/recordInk 경고 13개다. Android·큰 글자 접근성 설정·실제 서버 쓰기·장시간 스크롤 성능은 이번 시뮬레이터 점검 결과에 포함하지 않는다.
