## 공유하는 시각 규칙

정본: `src/features/home/components/record/pages/recordPageSpec.ts`.

- 좌우 20pt, 4pt 단위 간격. 섹션 간 24pt, 라벨과 컨트롤 사이 8pt.
- 제목 26/34, 섹션 제목 16/24, 선택·본문 14–16, 설명 14/20. 큰 숫자는 체중·혈당 40, 혈압 34, 수분 합계 36. 수치에는 tabular figures.
- 입력 패널 16pt 모서리, 선택 컨트롤 12pt, CTA 14pt. 최소 터치 영역 44pt, 저장 버튼 기본 52pt.
- 중립 배경과 읽을 수 있는 회색 라벨. 주황은 입력 초점·핵심 행동·복용 확인에 제한한다. 시간 라벨은 틴트 배지 없이 표시한다.
- 날짜는 상단 공통 헤더. 기록 설명 → 주 입력 → 필요한 조건 → 기록 이력 → 고정 저장 행동 순서.
- 키보드가 올라오면 저장과 내리기 버튼을 키보드 위로 이동시킨다. 고정 영역의 실측 높이로 본문 하단 여백을 확보한다.

## 페이지별 개정

### 수분

대형 컵을 보조 그림으로 줄이고 합계와 단위를 한 줄로 정렬한다. 건강 상태에 따른 수분 안내는 합계 아래에 붙인다. 100/200/300mL 버튼, 직접 입력, 추가한 항목별 삭제, 세션 합계 저장을 유지한다. 합계에는 저장 전 입력도 포함되므로 라벨을 ‘오늘 마신 수분’으로 바꾼다. 안내 두 줄 공간을 미리 확보해 양이 바뀌어도 선택 버튼이 갑자기 이동하지 않는다.

### 혈압

두 측정값은 같은 크기와 기준선으로 배치한다. 단위는 기본 크기에서 수치 옆, 큰 글자에서 아래로 이동한다. 시간대·측정 시점을 별도 그룹으로 나눈다. 선택 정보인 심박수는 접을 수 있고, 접힌 상태에는 입력한 값만 요약한다. 접을 때 키보드를 내리고 입력값은 유지한다.

### 혈당

공복은 혈당 수치와 측정 시점만 표시한다. 식전·식후일 때 끼니를 펼치고, 식후에만 경과 시간을 추가로 펼친다. 반복 설명을 제거하고 이력 위에 얇은 구분선을 둔다. ‘미지정’을 포함한 끼니 네 개는 기본 크기에서 한 줄, 글자가 크면 두 줄로 재배치한다. 문맥 변경·이전 셀 복귀 시 초안을 유지하는 기존 폼 로직을 사용한다.

### 체중

체중 입력 → 전날 대비 → 7일 기록의 위계를 유지하면서 입력 패널과 이력 행 높이를 줄인다. 감소·증가를 무조건 긍정/부정 색으로 표현하지 않는다. 실제 저장값과 예시 입력은 각각 네이티브 입력/별도 placeholder로 구분한다.

### 부기

처음에는 부위만 고른다. 부위를 고르면 그 부위의 정도가 펼쳐지고, 붓기가 있는 경우에만 눌린 자국 질문을 펼친다. ‘오늘은 붓지 않았어요’는 전체 상세 영역을 자연스럽게 접으며, 해제하면 기존 부위·정도·자국 입력을 복원한다. 저장 성공 전까지 이 지름길 선택이 다른 초안을 삭제하지 않는다. 등록된 부위 체크와 요약은 실제 관찰 데이터에 기반한다.

### 약 복용

오늘의 합계 → 시간대 → 해당 시간대 약 → 추가/관리 → 저장 순서다. 약이 없으면 의미 없는 네 개 빈 시간대 컨트롤과 0/0 분수를 숨긴다. 체크·시간·용량을 서로 다른 위계로 표시한다. 추가/설정 화면도 같은 여백·선택·저장 패턴을 사용한다. 실제 영속 로직은 `SPEC-v2.md`를 따른다.

## 모션과 큰 글자

- 선택 컨트롤은 UI 스레드에서 0.98 눌림 → spring 복귀, 선택 테두리 220ms 전환을 사용한다.
- 관련 질문은 높이 측정 후 약 260ms 접기/펼치기. 초안을 가진 하위 트리는 언마운트하지 않고, 숨길 때 터치 및 접근성 탐색에서 제외한다.
- 수분 추가·삭제는 기존 220–240ms 행 전환을 유지한다. 모든 애니메이션에 시스템 동작 줄이기를 반영한다.
- 전역 Text/TextInput 래퍼에서 기본 글꼴과 크기를 유지하면서 확대 상한을 역할별로 구분한다: 본문 1.5, 작은 설명 1.6, 제목 1.35, 큰 표시값 1.25, 컨트롤·입력 1.3. `allowFontScaling=false`로 일괄 차단하지 않는다.
- 인라인 강조는 부모의 확대 한도를 상속한다. iOS 글자 크기 변경 시 네이티브 텍스트 프레임을 다시 측정해 이전 크기의 빈 공간/말줄임이 남지 않게 한다.

## 검증 경계

기기 캡처와 실제 탭·입력 결과는 `REVIEW.md`에 기록한다. 자동 테스트 통과를 스크롤 프레임 성능·실물 카메라·운영 알림 전달의 증거로 취급하지 않는다.

## 공통 헤더·입력 후속 수정

- 날짜는 중앙 정렬을 유지하고, 약 추가·수정 같은 흐름 제목은 뒤로가기 옆에 둔다. `RecordPageShell.navigationTitle`로 날짜와 일반 제목을 구분한다. 약 수정이 약 추가로 표시되던 제목도 구분한다.
- 기록·약 등록 흐름의 불투명 헤더 아래에 중립 구분선을 두어 스크롤 본문과 경계를 만든다. 중앙 제목은 양쪽 액션 중 큰 폭만큼 대칭으로 비워 긴 우측 액션에 가려지지 않게 한다. 글자 크기는 늘리지 않는다.
- `NativeText.TextInput`과 `V2SheetTextInput`이 동일한 `inputMetrics`를 적용한다. 모든 스타일 덮어쓰기 뒤에 한 줄 입력의 문단 `lineHeight`를 제거하고 네이티브 수직 중앙을 사용한다. iOS에서 아래로 밀리던 placeholder와 입력값을 함께 바로잡는다.
- 여러 줄 입력은 문단 간격과 의도한 상단 정렬을 유지한다. 시트 입력은 gorhom의 입력·포커스·ref 경로를 유지해 키보드 추종이 끊기지 않게 한다.
- 직접 RN/gesture-handler/gorhom 입력을 가져와 공통 보정을 우회하는 경로를 AST 검사에 포함한다.
