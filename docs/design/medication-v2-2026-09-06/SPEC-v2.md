# 약 복용 v2 — 제품·동작 명세

2026-09-06. 첨부된 26쪽 v1 기획서와 M3–M11 시안을 검토해 개정한다. 원본 파일은 보존한다. 구현 및 검수 상태는 GATES.md/REVIEW.md를 따른다.

## 경험의 중심

홈의 약 복용을 누르면 선택 날짜의 독립 기록 페이지를 연다. 다른 다섯 건강 기록 페이지와 같은 날짜 헤더, 제목, 20pt 좌우 여백, 4pt 간격 체계, 중립 표면과 주황 행동 색을 사용한다. 약별 체크 원만 강조하고 시간·식사 조건에는 과한 틴트 배지를 쓰지 않는다.

흐름: 홈 → 약 복용 기록 → 약 추가 → 이름 검색 / 사진으로 찾기 / 직접 입력 → 복용 정보 설정 → 기록 페이지. 설정·사진 단계는 독립 페이지로 이동한다. 추가 화면을 나가도 기존 복용 체크 초안은 유지한다.

## v1에서 유지하는 로직

- RQ-01–10: 아침·점심·저녁·자기 전, 선택과 서버 저장의 구분, 전체 선택, 약별 복용 표시, 미저장 이탈 확인, 미래 날짜 기록 금지, 지난 날짜는 시각을 추정하지 않음.
- RQ-14–20: 검색 250ms 지연, 2글자 이상, 이름/성분/초성/한 글자 오타, 출처 표시, 없음과 연결 실패 구분, 직접 입력 대안.
- RQ-21–30: 세 등록 경로가 같은 설정 폼 사용, 시간대 복수 선택, 복용량·단위·식사 조건, 알림, 등록 직후 첫 선택 시간대 복귀. 중복 등록은 기존 약 수정과 별도 등록을 명시적으로 선택.
- RQ-31–40: 외부 카탈로그와 사용자 약 분리, 검증된 적재본만 활성화, 급격한 감소/빈 파일은 차단, 검수된 가이드만 노출.
- RQ-41–52 / AC-01–20: 앞·뒷면 사진, 촬영 사진 확인, 명확한 후보 확인, 실패 시 재촬영/검색/직접 입력. 네트워크 오류는 사진을 보존. 알 수 없는 약을 생성하지 않음.
- RQ-53–58: 명시적으로 켠 시간대 알림, 약 이름을 잠금화면에 노출하지 않음, 해당 날짜·시간대로 이동, 저장 완료 시 남은 알림 취소.
- EX-03–15: 등록·저장 실패 초안 보존, 잘못된 입력 방어, 연속 실패 시 검색 우선, 과거 기록 보존, 삭제/일시중지/수정과 재개.

## v2에서 바로잡는 결정

1. **자동 선택과 정확도 퍼센트 삭제.** v1의 90/70/50 점은 검증된 확률이 아니다. 후보는 모두 미선택으로 시작하고 각인·모양·제조사를 대조해 직접 고른다. 무각인·낮은 품질은 후보 제시를 거절한다. 사진 인식은 검증된 카탈로그와 평가 통과 설정이 모두 있을 때만 활성화한다.
2. **임의 처방 기본값 삭제.** 시간대, 1회 복용량, 단위를 사용자가 입력한다. 0.5정/1정 등 자동 처방, 제형만 보고 쪼개 먹기를 추천하지 않는다. 식사 조건은 ‘별도 안내 없음’으로 시작하고 ‘식사와 함께’를 추가한다. 식사 조건이 자동으로 알림 시간을 바꾸지 않는다.
3. **알림은 선택 동의.** 기본 OFF. 켜는 시점에 권한을 확인하고 실제 설정 시각을 보여준다. 약 저장 성공과 기기 알림 예약 성공을 분리한다. 기기 알림은 이 기기에서 작동하며 앱 재방문 시 예약을 갱신한다. 재알림/긴급 알림을 의료적 필요처럼 자동 활성화하지 않는다.
4. **날짜를 몰래 바꾸지 않는다.** 홈에서 고른 날짜가 기준이다. 자정 후 자기 전도 화면에 표시된 날짜에 저장한다. 알림은 예약 당시의 날짜를 전달한다. ‘오늘’ 기본 진입만 현재 KST 날짜를 사용한다.
5. **모든 변경을 한 번에 저장.** 탭 이동은 초안을 유지한다. 저장 버튼은 여러 시간대의 변경을 원자적으로 확정한다. 개수는 확인된 서버 응답만 반영한다. 통신 재시도에는 같은 요청 ID를 쓰고, 다른 기기의 수정과 충돌하면 조용히 덮어쓰지 않는다.
6. **과거 사실과 현재 설정 분리.** 일정은 적용 날짜별 버전으로 보존한다. 복용 기록에는 당시 이름·용량·단위·조건을 스냅샷으로 저장한다. 약 이름 수정·일시중지·삭제로 지난 기록이 바뀌지 않는다.
7. **가이드의 근거.** v1 예시를 효능군 전체의 복용법으로 복사하지 않는다. 검수자·검수일·제품 근거가 있는 가이드만 보여준다. 안내가 없을 때는 안내를 생성하지 않는다. 사용자 선택은 의료적으로 검증된 식별 정답으로 간주하지 않는다.

## 영속 데이터와 동시성

- 내 약: 계정 소유 ID, 현재 버전, 적용일, 이름/카탈로그 참조 스냅샷, 슬롯, 복용량·단위, 식사 조건, 알림 여부/시각, 활성·일시중지·보관 상태.
- 버전: 약 ID, 적용 날짜, 전체 설정 스냅샷. 같은 날 수정은 새 버전으로 기록하되 해당 날짜 최신 버전 조회.
- 하루 기록: 계정+날짜 단위 체크 목록과 서버 revision. 날짜+약+슬롯은 최대 한 건. 과거 입력은 timeKnown=false.
- 쓰기 요청: 계정+요청 ID, 본문 지문, 확인된 결과. 동일 본문의 재전송은 같은 결과를 반환하고 ID 재사용 충돌은 거절한다.
- 목록 저장과 일정 변경은 계정 단위 DB 트랜잭션 잠금으로 직렬화한다. 서버 검증은 소유권·날짜·활성 슬롯·revision·용량 범위를 모두 확인한다.

## 외부 연동과 출시 기준

2026-09-06 조사 시 의약품 카탈로그/API 키가 프로젝트에 없었다. 검색/사진은 실제 카탈로그 상태를 보고 기능을 제공한다. 하드코딩한 예시 약을 운영 검색 결과처럼 보여주지 않는다. 검색 데이터 출처는 실제 활성 데이터셋에 기록된 출처만 표기한다.

사진: 공급자 출력은 약명 생성에 쓰지 않고 사진 품질·각인·색상·모양 추출에만 사용한다. 실제 카탈로그 후보와 대조하며 외관 정보가 부족하면 실패로 처리한다. 모델 처리 시간 상한·최대 사진 수/크기·요청 취소를 둔다. 촬영본 자체는 앱 세션과 처리 메모리에만 두며, 공급자 보관 정책 검토는 출시 조건이다. 평가셋과 운영 데이터 계약·가이드 검수는 구현 테스트로 대체할 수 없다.

알림: 설치된 Expo SDK55의 알림 API를 따른다. 기기 예약과 서버 푸시는 별개다. 기기 예약 기간/권한/다른 기기 수정 반영 한계를 숨기지 않는다.
