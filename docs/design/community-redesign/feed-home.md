# `feed-home` — 자유글 마지막 행 (canvas y 13848, 11 frames)

> **섹션 라벨과 내용이 다르다 — 먼저 읽을 것.**
> 이 구역 바로 위의 검은 섹션 헤더(`rect x141 y13617 w4445 h131`)는 **"자유글- 홈화면"** 이라고
> 적혀 있지만, 그 아래 11개 프레임 중 **커뮤니티 홈 피드(탭바·검색바·실시간 인기글 레일·
> 정렬 컨트롤·글쓰기 FAB·하단 탭바)는 하나도 없다.** 실제 내용은
> **작성자 프로필 · 팔로워/팔로잉 목록 · 스토리 뷰어 · 스토리 촬영 · 게시글 상세 · 글쓰기** 다.
> 즉 이 행은 앞 섹션들의 재수록(또는 라벨 오기)이다. 진짜 홈 피드는 캔버스 위쪽
> `y12254 "자유글- 인기글, 식단, 최신 게시글 / 더…"`, `y4629`/`y7024 "자유글- 인기글, 최신 게시글 / …"`
> 섹션에 있다(다른 담당자 구역). 이 문서는 **내 구역에 실제로 그려진 것**을 스펙으로 적는다.
> "이런 작성자도 만나보세요" 블록과 홈 피드용 팔로우 버튼은 이 구역에 **없다**
> (팔로우/팔로잉 버튼은 프로필 헤더와 팔로잉 목록 행에만 있다).

## 측정 방법 (숫자의 근거)

- 모든 좌표는 SVG 원본에서 파싱한 값이다(@1x px). 프레임 원점 기준 상대좌표로 적었다.
- 글자 크기는 **눈대중이 아니라 Pretendard 실제 메트릭으로 역산**했다.
  `assets/fonts/Pretendard-*.otf` 를 직접 파싱(upem 2048, capHeight 1448=0.707em,
  한글 advance 1770=0.8643em, hheaAsc 1950/desc −494)해서
  `fontSize = 잉크폭 / (문자열 advance − lsb(첫) − lsb(끝))` 로 풀었다.
  긴 문자열은 오차 <0.5%(예: 카드 제목 → 15.00, 요약 → 13.00, 상세 본문 → 13.00).
  짧은 문자열(2~3자)은 2~4% 낮게 나오므로 정수 스케일로 올림 판정했다.
- 줄높이는 여러 줄 텍스트의 **줄별 잉크 top 차이**로 직접 측정했다(상세 본문 20.0 / 글쓰기 설명 23.0).

# 5. 상태 머신 / 인터랙션

**프로필 (F1/F2 → F3)**
- 팔로우 버튼은 2상태 토글: `팔로우`(weak, 브랜드 글자) ↔ `팔로잉`(fill, 흰 글자).
  크기·radius·위치는 두 상태가 완전히 동일하므로 **면/글자 색만 교체**(레이아웃 점프 없음).
- 탭 3개(후기/게시글/스토리) 중 `게시글` 선택 상태만 그려져 있다. 나머지 두 탭의 내용은 이 구역에 없음.
- 통계 3개 중 팔로워/팔로잉은 각각 F4/F5 목록으로 이동하는 탭 타깃(디자인에는 표시 없음, 현행 구현과 동일 가정).
- 로딩·빈 상태·에러 상태 프레임 **없음**.

**목록 (F4 vs F5)**
- 팔로워 목록에는 트레일링 버튼이 아예 없고, 팔로잉 목록에만 있다.
- 같은 목록 안에서 행마다 팔로잉/팔로우가 섞인다 → 버튼 상태는 **행 단위**.

**스토리 (F6 → F7 → F8)**
- 앱바 우측 `…` → 하단 액션시트(삭제하기 / 수정하기 / 취소). 시트는 dim + 아래에서 올라오는 플로팅 시트(좌우 10 마진).
- `수정하기`만 브랜드 테두리 + 브랜드 tint → **강조된 옵션**(파괴적 옵션 `삭제하기`는 오히려 중립 회색).
- 진행바(96/335 ≈ 29%)는 스토리 재생 진행. 다중 스토리라면 세그먼트가 아니라 **단일 연속 바**.
- 사진 위 카메라 배지 = 촬영 화면(F8) 진입 트리거로 보임.
- F8은 **키보드 올라온 레이아웃**: 시트(칩 레일 + 캡션 입력)가 키보드(292) 바로 위에 붙고,
  촬영 컨트롤(셔터/갤러리/전환)은 그 위 사진 영역에 남는다. 캡션에 캐럿이 있으므로 포커스 상태.
- 칩 레일은 단일 선택(1번만 브랜드) — CKD 단계/식이 태그.

**상세 (F9 → F10)**
- 앱바 `…` → 동일 액션시트(삭제/수정/취소) = **내 글 컨텍스트**.
- 정렬 컨트롤: 좌측 `최신순 ⌄`(드롭다운/시트를 여는 트리거), 우측 `마지막 댓글로`(점프 액션).
  펼친 상태 프레임은 없음.
- 댓글에 `작성자` 배지 → 글쓴이 표시. 대댓글은 배경면(`fill.alternative`) + 12 들여쓰기로 구분.
- 좋아요는 **표시만**(지표행 숫자). 상세에 좋아요 버튼 UI가 없다 — 현행 구현과 충돌(§7).
- 사진은 폭이 제각각(180/135/240)인 **가로 스크롤 스트립**(높이 180 고정, 원본 비율 유지).

**글쓰기 (F11)**
- 필수 필드는 라벨 뒤 브랜드색 `*`(제목·설명 작성), 선택 필드는 회색 `(선택)`.
- 사진 레일: 첫 칸이 추가 버튼, 이후 각 사진에 삭제 배지. 가로 스크롤.
- 태그: 입력 필드 + 그 아래 선택된 태그 칩(각 칩 X 로 제거), 최대 5개.
- 설명 필드에 `145/700` 글자수 카운터.
- 등록 CTA 는 **활성(브랜드 솔리드)** 상태만 있음 — 비활성/로딩 상태 프레임 없음.
- 스크롤 페이드가 CTA 바 위 36px 에 걸린다(콘텐츠가 CTA 밑으로 이어짐을 표현).

## 부족한 것 / 충돌 (그대로 두면 안 되는 것)

1. **21px 높이 칩이 v2 에 없다.** `V2Chip` 은 s=32 / m=38 뿐인데, 피드·상세의 태그 칩은
   **높이 21 · 라벨 10px · 좌우 패딩 7.5 · gap 6** 이다. 32짜리로 대체하면 카드 높이가 11px 늘고
   행 높이 공식(176/147/106)이 전부 깨진다.
   → **최소 추가**: `V2ChipSize` 에 `"xs" = { height: 21, paddingHorizontal: spacing[8],
   text: typography.caption.xSmall(10 semibold) / caption 계열 10 medium }` 를 넣는다.
   `controlHeight` 에도 `xs: 21` 을 추가해야 사다리가 깨지지 않는다.
2. **10px 라벨 토큰**: `typography.caption.xSmall` 이 10/15 SemiBold 로 있다. 태그 칩은
   Medium 으로 보이므로 `caption.xSmallWeak (10 medium)` 한 줄 추가가 필요할 수 있다(확인 필요).
3. **15/20 SemiBold·Bold 조합이 없다.** 카드·상세 제목이 15px + lineHeight **20** 인데
   v2 에는 `label.small` 15/19 SemiBold, `label.smallStrong` 15/19 Bold, `subtext.large` 15/20 Regular 뿐.
   → 19 로 내리면 카드 텍스트 블록 44가 42가 된다. **`label.smallTitle = 15/20 Bold` 추가** 또는
   블록 높이를 42로 재조정(디자인과 2px 차이) 중 택1. 스펙 값은 20이다.
4. **15/23 (글쓰기 설명 본문)** — 토큰 없음(가장 가까운 `subtext.large` 15/20).
   실측이 정확히 23.0 이므로 토큰 추가 또는 20 으로 통일 결정 필요. 20으로 통일 권장(필드 높이 186은 유지 가능).
5. **12px 텍스트가 두 군데**(카드 시간 "2시간 전", "마지막 댓글로"). `typography.subtext.small` 12/16 존재 ✓.
   다만 **같은 줄 안에서 13과 12가 섞이는 것**(지표행)은 시스템적으로 나쁘다 →
   13(`subtext.medium`)으로 통일 권장. 통일하면 시간 텍스트가 ~3px 넓어진다(우측 정렬이라 안전).
6. **좌우 여백 20 vs `GUTTER`=16.** 이 구역은 **전부 20** 이다(카드·목록·상세·글쓰기·시트 CTA).
   v2 `layout.GUTTER` 는 16. → 커뮤니티 화면 전용으로 20을 쓰려면 `layout.ts` 에
   `COMMUNITY_GUTTER = spacing[20]` 을 명시적으로 두고 이유를 적어야 한다(암묵적 리터럴 20 금지).
7. **뒤로가기 chevron 색 `#2E2F33` @0.88** 은 v2 에 없는 값이다(label 은 0.7/0.51/0.28/0.16 단계).
   → **`label.normal`(#2A2A37)** 로 치환한다(`V2ScreenHeader` 가 이미 그렇게 그린다). 육안 차이 없음.
8. **앱바 타이틀이 가운데 정렬**인데 `V2ScreenHeader` 는 뒤로가기 오른쪽 **좌측 정렬**이다.
   → `V2ScreenHeaderProps` 에 `titleAlign?: "left" | "center"` 추가(기본 left 유지)가 최소 변경.
9. **`letterSpacing`**: 디자인은 아웃라인이라 직접 확인 불가하지만, 실측 잉크폭이 Pretendard
   기본 advance 와 0.5% 이내로 일치 → **letterSpacing 0** 이다. 현행 구현의 `-0.24 ~ -0.4` 는 전부 제거.
10. **`fontWeight` 병기 금지**: 현행 코드가 `fontFamily` + `fontWeight:"700"` 을 같이 준다.
    v2 규칙(typography.ts 머리말)대로 **face 만** 남긴다.
11. **탭 레일 폭 233**: `V2Tab alignment="fixed"` 는 컨테이너 전폭을 균등 분할한다. 디자인은
    x20 에서 시작하는 폭 ~233 레일이다. 전폭(375)으로 펴면 라벨 중심이 62.5/187.5/312.5 로 이동한다.
    → 디자인 의도 확인 필요. 확인 전에는 폭 233 컨테이너에 `fixed` 를 넣어 디자인과 픽셀 일치시킬 것.
12. **시트 옵션 radius 24 / 높이 55** 는 `V2Option`·`V2ListRow` 어디에도 없는 조합.
    `radius["3xl"]`(24) 는 있으니 값은 표현 가능. 옵션 행 컴포넌트만 새로 만들면 된다.
13. **디자인 자체 버그 2건(그대로 구현하지 말 것)**
    - F8 첫 칩 `CDK3` → **CKD3** 가 맞다(F11 은 CKD3).
    - F11 라벨 x정렬: 카테고리/제목/태그는 x24, 설명 작성만 x20. → **전부 20으로 통일**.
    - F8 좌·우 원형 버튼 라벨이 둘 다 `전체` → 실제 카피 확정 필요(갤러리/전환 등).

- F11 설명 본문 **6번째 줄** — 하단 CTA 바와 페이드에 가려 판독 불가.

- 프로필 탭 레일 폭 233(전폭 아님)이 의도인지 미확정.
- 프로필 통계 3열의 우측 여백 60.7 이 의도인지 미확정.
- 상세 화면 하단 댓글 입력 바의 존재/치수(프레임 840 밖).
- 굵기(Regular/Medium/SemiBold/Bold)는 아웃라인이라 **획 두께 육안 판정** — ±1단계 오차 가능.

  (사진 자리의 흰 면은 "빈 상태"가 아니라 **누락 애셋**이다).
