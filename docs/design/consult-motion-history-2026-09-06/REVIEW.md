# AI 상담 진행 표시 · 결과 순서 · 상담 기록 개선

2026-09-06. RN 상담 화면 변경. 로컬 API 8100 / Metro 8085 / iPhone 17 Pro, iOS 26.5에서 확인했다. 백엔드 모델·도구 계약·조회 예산·기록 데이터에는 이번 변경이 없다.

## 문제와 변경

진행 표시의 깜빡임은 빠른 조회에 더해 두 가지 렌더링 경로가 겹친 문제였다. 조회가 완료된 뒤 아직 종료되지 않은 `thinking` 이벤트가 다시 선택됐고, 첫 도구 이벤트가 오면 헤더의 루트가 View에서 Pressable로 바뀌어 쉬머도 새로 마운트됐다.

- 헤더 호스트를 유지한다. 실제 조회가 생기면 같은 영역에 상세 열기 기능만 활성화한다.
- 240ms보다 짧은 중간 상태는 건너뛰고, 활성 진행 문구는 최소 640ms 유지한다. 오래된 상태를 차례로 재생하지 않고 최신 상태만 반영한다. 완료·실패·사용자 중단은 대기 없이 반영한다.
- 조회 후 초기 상태로 돌아가지 않는다. 본문이 시작되면 답변 단계가 우선한다. 진행 중 쉬머를 유지하고, 완료 후에는 실제 조회 내역만 접힌 상태로 남긴다.
- 새 답변의 영양·레시피 카드는 스트리밍 중 보류한다. 최종 본문 표시 후 120ms에 카드를 마운트하고 200ms 페이드인한다. 카드 추가 직전에 자동 따라가기를 멈춰 읽던 본문 위치를 유지한다. 사용자가 `최근 답변`을 누르면 아래로 이동한다.
- 이미 저장된 상담을 열 때는 카드를 즉시 표시한다. 실패·재시도·언마운트 때 이전 턴의 대기 타이머를 정리한다. 사용자가 중단한 경우에는 중단 상태를 명시하면서 이미 완료된 실제 조회 결과를 확인할 수 있다.
- 도구 내역, 재료, 만드는 법, 영양 계산 기준은 같은 측정 높이 기반 220ms 펼침·접힘을 사용한다. 내용과 화살표가 함께 움직이고 애니메이션 도중 방향을 바꿀 수 있다. 닫힌 내용은 바로 터치·접근성 대상에서 빠진다. 최초로 연 내용은 닫히는 동안 유지해 순간 사라짐을 막는다.

위 시간값은 구현 정책이며 모델 응답 시간 개선을 측정한 수치가 아니다. 공개 진행 이벤트만 표시하며 내부 추론이나 도구 인자를 노출하지 않는다.

## 상담 기록

기록은 드래그 핸들과 반투명 배경이 있는 시트에서 전체 페이지 형태로 변경했다. 상담 라우트 안에서 관리해 진행 중 요청과 작성 중인 질문의 소유권은 유지한다.

- 뒤로가기·상담 기록 제목·새 상담을 고정 헤더로 정리했다. 페이지 진입 260ms, 닫기 220ms의 수평 전환을 사용한다.
- 검색 필드와 조작 영역은 44pt 이상으로 유지하면서 제목 15pt, 시간 12pt, 요약 13pt로 정보 위계를 나눴다. 날짜별 목록은 가상화를 유지한다.
- 현재 상담은 중립 배경과 `열어 둔 상담` 표시로 구분한다. 제목에 덧붙은 문맥 블록은 목록에서 제외하고 제목과 같은 요약은 중복 표시하지 않는다.
- 검색 결과 개수, 검색어 지우기, 검색 결과 없음 복구, 불러오기 실패 재시도를 정리했다.
- 제목 수정창을 별도 입력칸·취소·저장 버튼으로 분리했다. 창 전체가 하나의 버튼으로 인식되던 접근성 문제를 고쳤다. 빈 이름은 저장할 수 없으며 취소할 때 키보드와 수정창이 닫히고 검색 상태가 유지된다.

## 검증

`GATES.md`의 12개 Jest suite를 재실행해 통과했다. 짧은 상태 병합·종료 즉시 반영·타이머 정리·본문 후 카드 표시·기존 기록 즉시 표시·재시도 격리·실측 높이와 빠른 방향 전환·닫힌 내용 접근성·복사 내용·세션·스크롤·검색·제목 수정 취소를 확인한다. 타이머와 Reanimated를 모킹한 검증은 아래 네이티브 확인과 구분한다.

`npx tsc --noEmit`, 변경한 16개 소스 파일 ESLint, 해당 경로 `git diff --check` 모두 exit 0. UX 문구 감사는 exit 0이며 기존 후보 12건(S1 9, S2 3)이 남는다. 이번 상담 문구에 새 후보는 없다.

실제 로컬 모델 상담에서 목표·오늘 섭취량·레시피 검색·레시피 상세 4건 조회를 확인했다. 기록 없음은 0으로 바뀌지 않고 `—`와 안내로 남았다. 본문 두 문단이 먼저 완성되고, 카드가 뒤이어 나타나는 프레임을 확인했다. 본문 위치는 카드 등장 전후 유지됐다.

- [최종 녹화](consult-live-motion.mp4): 27초. 약 7초부터 재생성, 약 17초부터 본문, 약 18초 이후 카드, 끝부분 도구 상세 펼침·접힘. 첫 6초는 직전 완료 답변이다.
- [본문 완료 후 카드 등장 프레임](handoff-frames.jpg): 최종 녹화 17.7초부터 10fps, 왼쪽에서 오른쪽·위에서 아래 순서. 본문 완료 → 카드가 없는 프레임 → 카드 페이드인 순서.
- [상세 전환 프레임](disclosure-frames.jpg): 최종 녹화 24초부터 5fps. 측정된 높이 변화와 화살표 회전. 검은 칸은 영상 끝 이후 빈 타일이다.
- [상담 기록 페이지](history-page-final.png), [답변과 카드](answer-final.png), [재료 펼침](recipe-expanded.png), [계산 기준 펼침](nutrition-basis-expanded.png).

기기에서 재료·도구·계산 기준을 열고 닫았으며 닫힌 내용이 접근성 목록에서 빠졌다. 생성 멈추기 → 중단 표시 → 다시 받기 → 정상 완료를 확인했다. 220ms 이내 방향 전환의 결정적 검증은 모킹 테스트이며 네이티브에서는 반복 탭과 중간 프레임을 확인했다.

기록 화면에서는 없는 검색어의 빈 결과와 지우기 복구, 기존 테스트 상담 검색, 검색 결과 1개 표시, 관리 메뉴, 제목 수정창의 분리된 입력·버튼, 빈 제목 저장 비활성, 다른 제목 입력 후 취소, 원래 제목·검색어 유지, 같은 상담으로 복귀를 확인했다. 건강 기록은 새로 생성하지 않았다.

첫 녹화에 개발용 Fast Refresh가 포함돼 최종 스트리밍 판단에는 사용하지 않았다. 코드 변경 없이 새로 녹화한 최종 영상에서 확인했다. 다크 모드·큰 글자·OS 동작 줄이기 모드는 이번 네이티브 재확인 범위에 포함하지 않았다. 동작 줄이기·백그라운드·화면 초점에 따른 모션 중단은 기존 및 추가 단위 테스트로 확인했다. 모델 지연의 통계적 개선이나 실제 기기의 프레임 성능을 보장하는 검증은 아니다.
