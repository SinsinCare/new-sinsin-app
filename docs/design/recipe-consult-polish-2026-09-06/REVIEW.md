초기 Codex 웹 검색에는 다른 앱(Lindy/Cohere/Gemini)이 섞여 있어 Codex 근거로 쓰지 않았다. Manus 예약 작업 흐름도 실시간 대화의 주 참고로 쓰지 않았다. Mobbin 흐름 도구가 보여 준 중간 미리보기만 관찰했으며 전체 영상이나 애니메이션 프레임 속도를 측정했다고 주장하지 않는다.

API 구현은 기존 제공자 코드를 먼저 확인하고 [OpenAI 공식 function calling 문서](https://developers.openai.com/api/docs/guides/function-calling)를 참고했다. 모델의 reasoning 출력 항목은 후속 도구 라운드로 전달하되, 앱에는 내부 사고 원문을 전송하지 않는다. Gemini thought 파트와 OpenAI reasoning 아이템도 답변 텍스트에서 제외한다.

## 구현 범위

- `/consult`를 기본 카드 내비게이션의 독립 페이지로 전환했다. 홈·레시피·식사·검진·식당이 같은 페이지를 사용한다. 식당 정보는 해제 가능한 상단 맥락 행으로 보여 주고 첫 질문에 한 번만 포함한다.
- 새 상담·지난 상담·실패 재시도·첨부 메뉴와 입력창을 기능 단위로 분리했다. 추천 질문은 입력창에 넣은 뒤 수정할 수 있다.
- 서버 도구는 내 목표 조회, 오늘 섭취량/목표 비교, 앱 레시피 검색, 검색된 레시피의 재료·조리법 조회 네 종류다. 인증된 사용자 범위의 읽기 작업만 허용한다. 기록 추가·변경, 외부 웹 검색, 임의 코드 실행 기능을 만든 것은 아니다.
- 도구 라운드는 2회, 실제 실행은 최대 6회다. 인자·결과·응답 크기를 제한하고 반복 조회를 한 턴 안에서 재사용한다. 취소 신호는 도구 확인과 제공자 요청에 이어진다.
- 도구 이벤트에는 검증된 열거형 상태, 빈 기록 여부, 최대 4개 검색 결과 수와 실제 조회한 공개 레시피의 ID·제목만 포함한다. 도구 인자, 내부 프롬프트, 개인 사고 원문을 UI에 싣지 않는다.
- 질문 처리 → 필요한 조회 → 답변 정리를 접고 펼칠 수 있다. 마스코트는 생성 중에만 UI 스레드에서 2px 이동/2도 회전하며 900ms 왕복한다. 펼침은 140ms 페이드, 화살표는 160ms 회전이다. 동작 줄이기를 존중한다.
- 글자를 강제로 잘라 보여 주던 애니메이션을 제거했다. 서버에서 승인한 완성 청크를 80ms 단위로 묶어 표시해 숫자·단위·한글 부정어가 인위적으로 잘리지 않게 한다.
- 답변이 이미 완성된 계획 응답은 기존 문장·최종 응답 검증을 거쳐 재사용한다. 같은 답을 다시 생성하는 요청을 줄였다.
- 사용자가 위를 읽는 중에는 새 답변이 스크롤을 빼앗지 않고, 최근 답변으로 이동할 수 있다. 완료된 과정의 수동 펼침은 자동 하단 이동을 유발하지 않는다.
- 답변 재생성은 검증된 마지막 assistant ID를 명시한다. 성공한 경우에만 마지막 답변을 교체하며, 실패·중단 때 기존 저장 답변을 보존한다. 다른 대화/오래된 답변 ID는 거절한다.
- 레시피 상세는 제목·메타 정보·영양 값·단위의 위계와 20pt 거터를 정리했다. 이미지가 없을 때 큰 빈 영역을 줄였다.

## 실제 실행에서 찾아 수정한 결함

1. 공통 chat 서비스가 7번째 activity 콜백을 전달하지 않았다. 공개 서비스 경로까지 포함해 회귀 검사를 바꿨다.
2. 재생성이 새 질문/답변을 저장해 다시 열면 중복됐다. 명시적 교체 계약과 실제 테스트 DB 검사를 추가했다.
3. 진행 중 지난 상담 로드가 실패하면 중단된 답변이 정상처럼 남았다. 중지 상태를 유지하고 늦게 도착한 이전 결과를 무시한다.
4. 계획 단계가 이미 답을 완성해도 다시 생성하던 왕복을 줄였다.
5. 제공자 재시도 전의 실행 중 상태는 오류로 끝내며, 나중 완료가 거짓으로 덮어쓰지 않는다.

## 9월 6일 후속 보완: 상담 기록과 작업 이력

Mobbin에서 추가로 직접 확인한 [ChatGPT 최근 대화](https://mobbin.com/screens/2bc97dd2-3555-46a3-b7c2-ab2999dfa002), [Codex 대화 검색](https://mobbin.com/screens/635d1318-0af4-416f-9659-6ad171e0a783), [ChatGPT 보관함 검색](https://mobbin.com/screens/554db244-ada9-4e99-8be1-5d168c08eab8)을 참고했다. 작은 목록 행·검색·조용한 보조 동작이라는 위계를 적용했다. 마지막 화면은 로딩 중인 보관함이므로 완성된 대화 행 디자인의 근거로 쓰지 않았다. 이 검색 전에 나온 웹 검색 흐름은 상담 기록 검색과 목적이 달라 제외했다.

- 큰 새 상담 CTA를 헤더의 작은 버튼으로 옮기고, 최근 상담의 제목과 요약을 찾는 검색을 추가했다. 서버가 제공한 최근 200개 범위이며 전체 대화 본문 검색으로 표현하지 않는다.
- ScrollView의 전체 행 생성 대신 SectionList로 보이는 영역부터 렌더링한다. 15/21 본문, 13/18 보조 정보, 20 거터, 44 이상 관리 버튼 영역과 구분선을 사용했다. 화면 전체 글자를 확대하지 않았다.
- 생성 시각 대신 마지막 상담 시각으로 정렬하고 날짜 그룹을 나눈다. 예전 대화를 오늘 이어 쓰면 오늘 영역에 놓인다.
- 키보드가 열린 검색, 빈 검색 결과, 지우기, 새 상담을 실제로 확인했다. 기록 창이 열렸을 때 뒤쪽 상담 UI가 접근성 탐색에 함께 잡히지 않도록 분리했다. 동작 줄이기 설정에서는 기록 창과 행 메뉴의 진입 효과를 생략한다.
- `message.activity_json`에 최대 24개의 검증된 종료 상태만 저장한다. 역할·본문은 기존 컬럼을 유지한다. 원시 추론·도구 인자·결과 본문·알 수 없는 필드는 저장하거나 표시하지 않는다. 모델의 이전 대화 맥락에는 이 필드를 넣지 않는다.
- 답변이 성공했을 때만 본문과 이력을 같은 SQL 문장에서 저장·교체한다. 도중에 멈춘 도구가 성공으로 바뀌지 않으며 실패·중단한 재생성은 기존 답변과 이력을 유지한다. 소유권 검증 후에만 조회한다.
- 새 상담으로 현재 대화를 비운 다음 기록에서 테스트 질문을 다시 열고 펼쳤다. ‘도구 확인 2건’, ‘레시피 검색 4개 찾음’, ‘재료와 조리법 확인 완료’가 그대로 복원됐다. [복원된 작업 이력](consult-restored-activity.png), [상담 기록 목록](consult-history-list.png), [검색 빈 결과와 키보드](consult-history-search-empty.png).
- 후속 검증: 프런트 4개 스위트 26개 검사, 서버 3개 파일 36개 검사 및 기존 스트림 비교 64개 검사 통과. 프런트·서버 타입 검사와 변경 파일 ESLint 통과. `GATES-history.md`에 실행 결과를 기록했다. 이전 검증 수와 중복되므로 합산하지 않는다.

스키마 변경은 기존 소유자인 legacy Alembic의 096 리비전에 작성했다. 검증된 loopback의 로컬 TEST `sinsin`·분리 테스트 `sinsin_bench`에 이 nullable 컬럼 하나만 추가했으며 이전 마이그레이션이나 버전 표시는 진행하지 않았다. 배포 시에는 096을 먼저 적용해야 한다. 운영 반영은 하지 않았다.

다음 품질 점검 대상은 긴 대화에서 펼치기/닫기와 스크롤 유지, 실제 조회한 자료로 이어지는 동작, 답변 문구의 간결함이다. 이번 실제 답변에는 단순 재료 질문에도 반복적인 의료 면책 문장이 붙었다. 이를 서비스 동등 품질로 평가하지 않으며, 긴 스크롤·다크·큰 글자 기기 검증 제한도 여전히 남아 있다.


## 9월 6일 후속 보완: 실제 자료 연결과 읽던 위치 유지

Mobbin의 [ChatGPT 답변 하단 출처 동작](https://mobbin.com/screens/8cf567ec-633b-4d0b-81b8-4e05de5fdb9c), [ChatGPT 출처 목록](https://mobbin.com/screens/3eaf4e44-fdce-48bc-965b-b194ed9c43ac)을 직접 봤다. 본문과 자료 열기를 분리한 위계만 가져왔다. 함께 검색된 Perplexity의 Keep Reading 화면은 추천 콘텐츠이므로 인용·출처의 근거에서 제외했다.

- 로컬 메시지 키를 서버 ID와 분리했다. 답변 완성 때 메시지가 새로 마운트되며 펼친 과정이 닫히던 문제를 해결했다. 서로 다른 레시피 조회는 실제 이름을 표시한다.

같은 질문을 재생성하며 프롬프트의 충돌을 확인했다. 일반 상담 규칙은 ‘세 항목부터 목록’과 ‘답변 전체에서 굵게 한 번’을 요구했지만 도구 상담은 두 항목 비교를 목록으로 쓰라고 했다. 한·영 도메인 규칙을 두 항목 비교에도 목록을 허용하도록 맞추고 항목의 이름·행동만 짧게 강조하도록 정리했다. 기존 프롬프트 정본과의 의도적 차이 등록에 변경 이유를 추가했다. 공통 보이스 계약과 응급·진단·개인 수치 제한은 유지했다.

## 9월 6일 후속 보완: 작성과 생성 중 이탈

Mobbin의 [ChatGPT/Codex 긴 초안 입력창](https://mobbin.com/screens/7c70cf97-e978-4684-9299-0e4f2fc72eae), [짧은 초안 입력창](https://mobbin.com/screens/bcd32d5b-87a4-46ff-9936-aa7489b675ab)을 직접 확인했다. 본문 입력과 첨부·전송 도구를 분리하는 위계를 참고했다. 이 정지 화면을 초안 보존이나 이탈 동작의 증거로 사용하지 않았다.

CUA 스크롤·드래그는 창을 Raise한 뒤에도 `-10005:noWindowsAvailable`로 실패했다. 이는 도구 오류로, 앱의 스크롤 결함이나 통과 증거로 해석하지 않는다. 다크 모드·큰 글자·동작 줄이기의 실제 설정 변경 검증은 컴퓨터 제어 정책에 따른 사용자 승인 답변을 기다리고 있어 수행하지 않았다. 기존 전체 품질 평가의 한계는 그대로 남아 있다.

## 9월 6일 후속 보완: 사진 첨부와 입력 포커스

Mobbin의 [ChatGPT/Codex 작은 첨부 메뉴](https://mobbin.com/screens/90c4f21a-8e70-466e-bc9f-473492eae957), [ChatGPT 사진·도구 선택](https://mobbin.com/screens/161451c9-1525-49cf-acbd-54ca75b43187), [ChatGPT 첨부 동작 배열](https://mobbin.com/screens/cf94f6ed-ad32-48c1-ad40-e8ee75e9615a)을 직접 확인했다. 신신당부는 현재 지원하는 사진 두 동작에 맞춰 첫 화면의 작은 메뉴 위계를 적용했다. 레퍼런스에 표시된 외부 검색·파일·연결 앱 기능을 구현했다고 주장하지 않는다.

- 실측 과정에서 메뉴를 열며 입력창의 접근성 요소를 강제로 숨기면 키보드가 닫히고 메뉴도 사라지는 것을 확인했다. 모달 접근성 범위로 뒤쪽 탐색을 제한하면서 입력 필드 자체는 유지하도록 수정했다. 최종 위치에서 키보드·초안·메뉴가 함께 유지되고, 접근성에는 두 메뉴 버튼과 키보드가 개별 노출되는 것을 확인했다. [키보드 위 첨부 메뉴](consult-attachment-menu-keyboard.png). 캡처 후 선택 라벨을 ‘앨범에서 선택’으로 짧게 다듬었다.

- 설치된 Expo ImagePicker의 `src/ImagePicker.ts`를 확인했다. 지원 OS의 시스템 사진 선택에는 전체 앨범 권한이 필요하지 않으므로 불필요한 사전 권한 요청을 제거했다. 카메라는 기존 권한 확인을 유지한다. 기존 사진 품질 0.8을 유지했고 자동 업로드를 추가하지 않았다.
- 사진 추가·제거 때 화면 전체를 움직이던 LayoutAnimation을 제거했다. 메뉴는 140ms 진입·100ms 퇴장 페이드를 쓰며 동작 줄이기에서는 생략한다. 첨부 삭제는 28pt 표시 안에 44pt 실제 터치 영역을 두었다.
- 시뮬레이터에서 메뉴 닫기·키보드 위 메뉴 유지·두 버튼 분리·네이티브 사진 선택창 진입을 확인했다. 테스트용 앱 아이콘을 사진 보관함에 추가했으나 사진 선택창 자체는 CUA 접근성 트리에 버튼이 없었다. 새 제어 세션으로 다시 연결해도 좌표 선택은 `-10005:noWindowsAvailable`로 실패했고 Escape·Tab도 선택/취소를 실행하지 못했다. 따라서 사진 선택 후 초안 복귀·사진 제거는 기기 검증 완료로 기록하지 않는다. 이미지나 질문은 전송하지 않았다.
- 선택 취소, 실패 후 재시도, 단일 선택창, 초안 초기화·해제 뒤 늦은 응답, 카메라 권한 거절·설정 이동 실패, 포커스 복원을 포함한 새 훅 검사 11개와 기존 이탈 검사 10개가 통과했다. 타입·표적 ESLint·문구 검사도 통과했다. 문구 검사의 기존 후보 12개는 별도이며 이번 추가 문구는 포함되지 않았다. `GATES-consult-attachments.md`에 실제 범위와 미검증 기기 경로를 남겼다.


## 9월 6일 후속 보완: 도구 조회와 본문 스트리밍 실측

실제 설정 모델 `gpt-5.6-luna`·추론 강도 `high`로 인사, 레시피 두 가지, 기록 없음, 기록된 0mg, 조회 실패를 평가했다. 개인 기록이나 DB에 접근하지 않는 합성 도구를 사용했고 프로덕션 도구 선언·공개 출처 추출·프롬프트·답변 가드를 그대로 거쳤다. 비교 결과와 원문은 [서버 평가 보고서](../../../../sinsin-be-bun/docs/consult-quality-2026-09-06/README.md)에 보관했다.

- 기존 단일 조회는 최종 답변을 비스트리밍 계획 요청에서 완성한 뒤 두 청크를 0–1ms 간격으로 배포했다. 도구를 고르는 요청 자체를 스트리밍으로 바꾸고 공개 본문도 기존 문장 릴리스와 최종 가드에 통과시켰다. 단일 조회는 첫 도구 선택·두 번째 본문으로 끝난다. 내부 종료 함수를 강제하는 실험은 세 번째 요청이 필요하고 지연이 늘어 최종 코드에서 제거했다.
- 완결된 제공자 응답에서만 함수를 실행한다. 잘린 인자·누락된 ID·미완료 응답·크기 초과에서는 읽기를 시작하지 않는다. 원시 추론·Gemini 서명은 다음 제공자 라운드에만 보존하며 공개 이벤트나 저장 이력에 넣지 않는다. 실제 읽기 6개·계획 2라운드 한도와 중단 시 상류 취소를 유지한다.
- 요청 오류 400이 일반 연결 오류로 처리되어 다른 제공자로 넘어갈 수 있는 경로도 바로잡았다. 503 전환은 같은 가드와 실제 도구 상태를 거친다. 공개 접두 문장이 도구 호출보다 먼저 오는 제공자 응답은 다음 본문과 문단을 분리하고 중복 생성하지 않는다.
- 최종 5개 사례를 두 번 실행했다. 두 레시피의 여섯 재료 분량·조회 출처, 기록 없음과 0의 구분이 일치했다. 실패 답변의 자동 후속 확인 약속을 없앴다. 두 번째 레시피 답변에서 재료명까지 전부 굵게 표시되는 사례를 확인해 이름만 강조하도록 다듬었고, 추가 실측에서 재료·분량은 보통 굵기로 돌아왔다.
- 최종 단일 조회는 두 번의 모델 요청이며, 첫 문장 뒤 나머지가 354–1,101ms에 걸쳐 이어졌다. 네트워크와 모델 지연의 변동이 있어 일관된 응답 속도 향상으로 단정하지 않는다. 별도의 제어 스트림 검사에서 완료 이벤트를 보내기 전에 실제 첫 문장이 소비자에게 도착하는 것을 확인했다.
- 도구·프롬프트·답변 가드·요청·제공자 전환·스트림 회귀 7개 파일 202개 검사와 타입 검사를 통과했다. 해당 수에는 도구 26개 검사가 포함되며 다른 검증 수와 합산하지 않는다. 결과는 `GATES-consult-quality.md`에 기록한다.

이번 증거는 모델·서버 계약의 확인이다. 시뮬레이터를 다시 열었지만 시스템 사진 선택창은 여전히 CUA 접근성 버튼을 노출하지 않았다. 최신 본문 스트리밍의 네이티브 화면 재검증, 사진 선택·취소 후 복귀, 연속 손가락 스크롤, 다크·큰 글자·동작 줄이기 확인은 완료로 표시하지 않는다. 기존 기기 제어 한계와 설정 변경에 대한 사용자 응답 대기는 유지된다.

최종 재확인: 앱 아이콘으로 신신당부를 다시 열어 사진 선택창이 유지되는 것을 확인했다. 최신 화면의 닫기 좌표 클릭도 `Computer Use server error -10005: noWindowsAvailable`로 실패했다. 같은 제어 제한이 이어져 해당 네이티브 검증은 사용자 조작 또는 제어 도구 복구가 필요하다. 마지막 상태 감사는 30개 충족·1개 미완료(첨부 A3)·1개 제외(연속 스크롤 도구 제약)이며, 이번 서버 품질 기준 4개는 모두 충족했다.

## 9월 6일 후속 보완: 진행 문구·시머·조회 내역

사용자가 제시한 화면은 질문 준비·건강 목표 조회·답변 정리를 같은 완료 목록에 넣어 실제 조회 1개가 세 단계로 보였다. 이제 진행 중 문구는 헤더의 같은 자리에서 교체하고, 펼친 내역과 개수에는 실제 조회만 포함한다. 중복 이벤트는 같은 ID의 행을 갱신한다. 저장된 이전 상담도 같은 표시 규칙을 사용하며 서버 데이터는 변경하지 않았다.

Mobbin에서 직접 본 [ChatGPT의 접힌 진행 내역과 실제 조회 상세](https://mobbin.com/screens/4fe4b960-ab35-4327-82b0-759ccbb0d825)를 핵심 위계로 참고했다. [Manus의 현재 작업 표시](https://mobbin.com/screens/59294d00-2e82-406d-a422-a8efa4cd10ab), [병렬 작업 진행 카드](https://mobbin.com/screens/8a153d98-64f5-4d63-a0c4-e079dd7511d5)도 비교했지만 큰 작업 목록은 이번 작은 상담 헤더에 적용하지 않았다. 검색 결과 중 보관 알림 화면은 주제에 맞지 않아 제외했다. 정지 이미지에서 시머 움직임을 관찰한 것은 아니며, 시머 자체는 이번 구현·네이티브 검증 결과다.

- 현재 작업 문구에만 글자색이 왼쪽에서 오른쪽으로 흐르는 시머를 적용했다. 1.5초 이동·0.7초 휴지의 중성 색상이며, 본문이나 캐릭터를 함께 반복 움직이지 않는다. 13pt/18pt 상태 문구, 13pt/16pt 브랜드 글자와 기존 여백 토큰을 유지했다. 캐릭터는 32pt, 펼치기 화살표는 16pt다.
- 실제 조회에는 건강 목표·섭취량·검색·레시피 아이콘을 사용하고, 반복되는 ‘완료’와 세로선·불릿을 제거했다. ‘기록 없음’, 검색 결과 개수, 실패·중단은 별도로 보존한다. 조회가 없는 답변에는 펼치기 동작과 화살표가 없다.
- 시머는 네이티브 텍스트의 색만 바꾼다. 글자 크기·위치·높이에 프레임별 변경을 주지 않으며 JS 반복 타이머나 새 네이티브 패키지를 추가하지 않았다. 완료·중단·화면 이탈·백그라운드·동작 줄이기·언마운트 때 취소한다. 늦게 도착한 접근성 설정 조회가 더 최근 OS 변경을 덮지 않도록 처리했다.
- 중단 시험에서 헤더와 본문에 중단 안내가 중복되는 문제를 추가로 발견했다. 헤더의 ‘답변 생성을 멈췄어요’ 한 번으로 통합하고, 빈 마크다운도 렌더링하지 않는다. 이미 받은 본문과 실제 조회 출처, 재시도 동작은 유지한다.

실제 iPhone 17 Pro / iOS 26.5 TEST 앱에서 건강 목표·오늘 섭취·레시피 2개를 요청했다. 완료 내역은 건강 목표, 기록 없는 섭취량, 4개 검색 결과, 두 레시피로 정확히 5개였다. 재시도 완료·생성 중단·저장된 답변 다시 열기, 조회 없는 인사 답변까지 확인했다. 기존 사진 선택창 제약이 해소된 현재 화면에서 수행한 증거이며, 이전 첨부 검증의 미완료 항목을 자동으로 통과 처리하지 않는다.

동작 줄이기·백그라운드·화면 포커스 변화는 프로덕션 훅을 실행하는 검사로 확인했다. 실제 OS 설정 변경, 큰 글자·다크 모드·물리 기기 VoiceOver·Android 검증을 수행했다고 주장하지 않는다. 접근성 요소를 읽는 CUA는 정적 View도 button으로 표시하므로, 네이티브 VoiceOver 발화까지 검증한 것으로 해석하지 않는다.
