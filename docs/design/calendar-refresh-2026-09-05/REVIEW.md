# 기록 달력 개선

## Mobbin 참고 화면

Mobbin MCP에서 13개 화면을 실제 이미지로 비교했다. 일반 웹 검색이나 생성 이미지를 레퍼런스로 쓰지 않았다.

- [Amie](https://mobbin.com/screens/a7f5018f-3a69-4263-922f-3ff223d59ede): 월 제목과 탐색 화살표를 분리한 가벼운 시트. 연·월 진입 구조와 단순한 날짜 선택을 참고했다.
- [pliability](https://mobbin.com/screens/71a51c06-3b92-44ca-906a-b6645b9f1002): 월 그리드에서 선택된 날짜를 가장 강하게 구분하고 기록 상세를 아래에 두는 위계. 과한 컬러 채움은 가져오지 않았다.
- [Fitbit](https://mobbin.com/screens/f2993c0c-39d2-4a3a-b5c8-49c1b6d512e1): 주·월 단위 전환과 기록 표시를 분리한 구조.
- [Asana](https://mobbin.com/screens/0290a0fb-78bb-4f8f-ac9c-b53d686c7b59): 날짜 영역 바깥의 빠른 날짜 이동. 이 앱에는 오늘만 필요하므로 오늘 버튼을 항상 유지한다.
- [FotMob](https://mobbin.com/screens/629641ad-40fe-46d2-b5c2-62214c13decd): 오늘과 닫기 동작을 달력 상단에 명시하는 구조.
- [Oura](https://mobbin.com/screens/05e196cc-efcf-485f-b381-dfae87373bb3): 날짜 숫자와 기록 마커의 시각적 역할 분리. 여러 종류의 기록 점이나 왕관은 이 앱 데이터에 맞지 않아 가져오지 않았다.

## 적용한 위계와 동작

- 월 28/36pt, 연도 13/20pt로 계층을 나눴다. 용도 설명은 15/22pt, 요일은 12/18pt, 날짜는 17/24pt다. Pretendard와 기존 중립 팔레트를 유지한다.
- 선택 날짜는 진한 채움, 오늘은 윤곽선, 식사 기록은 작은 주황 점으로 구분한다. 주황 배경 틴트와 여러 회색 도트는 쓰지 않는다. 선택된 날짜의 기록 점은 반전한다.
- 실제 조회 API는 식사 기록 존재 여부를 제공하므로 범례와 접근성 설명도 ‘식사 기록’이라고 표현한다. 모든 건강 기록이 있는 날로 오인시키지 않는다.
- 오늘과 닫기, 이전/다음 이동은 44pt 이상의 터치 영역을 가진다. 오늘은 선택 날짜가 오늘이더라도 계속 보여 과거 달을 탐색한 뒤 바로 복귀할 수 있다.
- 월 제목으로 연·월 선택을 같은 시트 안에서 연다. 별도 모달을 겹치지 않고, 월을 골라도 날짜 확정 전에는 실제 선택 날짜를 바꾸지 않는다. 날짜를 누르면 즉시 해당 기록으로 이동한다.
- 4~6주 달을 같은 6행 프레임에 배치하고 상태 안내 자리도 확보했다. 월 전환은 160ms 페이드만 사용한다. 시스템 동작 줄이기를 따른다. 큰 글자에서 본문이 화면 상한을 넘으면 내부 스크롤로 접근한다.
- 월·주 달력을 월요일 시작으로 맞췄다. 기존 주간 통계 API의 월~일 범위와 일치한다. 영문 월 달력만 일요일 시작이던 불일치도 해소했다.
- 일간 통계에도 같은 날짜 셀을 연결했다. 날짜 제목으로 월 달력을 열고, 통계의 날짜는 홈 선택 날짜와 별도로 유지한다. 리포트 응답 전후에도 날짜 제목이 바뀌지 않도록 로컬 날짜 포맷을 사용한다.
- 기록은 YYYY-MM-DD 전체 키로 연결한다. UTC 파싱으로 날짜가 하루 밀리거나 월 경계에서 일자만 잘못 연결되지 않게 한다. 닫힌 달력은 월별 기록을 새로 조회하지 않는다. 다시 열 때는 최신 기록을 조회해 닫힌 동안 저장한 식사도 반영한다.
- 기록 조회의 로딩·실패·알려진 빈 달을 구분한다. 실패 시 다시 불러올 수 있고 날짜 이동은 계속 가능하다. 날짜 선택은 건강 기록 저장을 수행하지 않는다.

## 검증

- iPhone 17 Pro / iOS 26.5, 기존 Metro 8085 테스트 세션. 새로운 빌드나 서버를 실행하지 않았다.
- 2026년 8월(6주), 9월(5주), 2021년 2월(4주)의 동일 프레임과 연도 이동, 오늘 복귀를 직접 확인했다.
- 9월 4일을 선택해 홈의 해당 날짜 기록으로 이동했다. 통계에서 9월 5일을 선택한 뒤 홈으로 돌아와도 홈은 9월 4일을 유지했다.
- 실제 통계 일간 화면의 요일·선택된 4일·오늘 테두리와 식사 점이 있는 5일·비활성 6일, 날짜 제목으로 월 달력 열기를 확인했다.
- 글자를 세 단계 키워 월/주 달력을 확인했다. 글자 크기를 바꾸면 iOS가 기존 텍스트를 잘못 그리는 현상을 재현했고, 배율 변경 시 텍스트 뷰를 다시 배치하도록 수정했다. 달력이 열린 상태에서 크기를 한 단계 낮춘 뒤에도 날짜가 표시되는 것을 확인했다. 남은 두 단계도 낮춰 원래 크기로 복원했다.
- 다크 모드 월 달력에서 선택한 4일, 오늘 테두리/식사 기록 점이 있는 5일, 미래 날짜의 구분을 확인했다. 점검 후 원래 라이트 모드와 오늘 날짜로 복원했다.
- 연월 선택의 큰 글자 배치, 커스텀 닫기 버튼으로 시트 종료를 확인했다. 건강 기록을 임의로 저장하지 않았다.

실제 iOS 화면 점검 결과와 자동 검사 결과는 GATES.md에 기록한다. 네이티브 레이아웃은 시뮬레이터로, 로딩/실패 분기와 콜백은 실제 컴포넌트의 렌더 검사로 구분해 검증한다. 후자는 네이티브 도형 배치나 터치 전달을 증명하는 검사가 아니다.
