# 댓글 키보드와 사진 스토리 후속 개선

- [x] 키보드 내리기를 반복해도 댓글 입력창이 화면 하단으로 복귀한다. 빈 입력 2회, 두 줄 입력 1회를 시뮬레이터에서 확인했다.
- [x] 빈 댓글 플레이스홀더가 입력 배경의 세로 중앙에 놓인다. 두 줄 입력/삭제 후 높이와 전송 버튼도 확인했다.
- [x] 스토리는 세로 사진 카드와 가로 목록으로 표현한다. 빈 상태/로딩/오류를 구분하고 차단·만료 필터와 진입 동작을 유지한다.
- [x] 관련 테스트, 타입, 변경 파일 린트, 한국어 카피 검사를 실행하고 결과를 확인했다. 카피 감사의 기존 전역 발견 항목은 아래에 구분한다.

## 디자인 기준

사용자가 첨부한 블라인드 스토리 화면을 우선했다. [Instagram 추천 릴스](https://mobbin.com/screens/f5ce72ad-1ae5-47d3-abde-989324593482) 실제 이미지도 확인했다. 사진 자체가 보이는 112×152 세로 카드, 하단 작성자명, 옆 카드가 이어지는 가로 목록으로 구현한다. 사진 기반 기능이므로 동영상 재생 아이콘이나 프로필 스토리 링은 쓰지 않는다.

빈 상태는 같은 높이의 사진 묶음 일러스트와 첫 스토리 진입점이다. 로딩은 사진 카드 스켈레톤, 실패는 안내와 재시도다. `V2EmptyState`의 빈 상태 노출 계측을 유지한다. 새 디자인에 반하던 이전 테스트의 특정 카피 금지 조건을 갱신하되 계측 계약은 유지했다.

## 동작과 확인 범위

수정 전 사용자 캡처에는 키보드가 사라졌는데 입력창만 중간 높이에 남아 있었다. 현재 세션의 수정 전 첫 재현에서는 정상 복귀했다. 기존의 RN 키보드 전역 LayoutAnimation, RN Animated sticky transform, JS 하단 여백 변경을 UI 스레드의 한 키보드 애니메이션으로 합쳤다. 닫힘 명령도 같은 KeyboardController를 사용한다.

2026-09-05 iPhone 17 Pro / iOS 26.5의 기존 Metro 테스트 세션에서 확인:

- 본문 상단에서 열기/닫기 3회. 매번 입력창이 원래 화면 하단으로 복귀했다.
- 두 줄 테스트 댓글 입력 후 닫아도 내용 유지. 입력 삭제 후 빈 플레이스홀더 중앙 정렬. 테스트 댓글은 게시하지 않았다.
- 빈 스토리 카드, 스토리 명칭, 사진 묶음 그림, 자연스러운 줄바꿈을 실제 화면에서 확인.
- 스토리 추가 화면 진입 및 복귀를 확인. 실제 서버에 현재 스토리가 없어 사진이 있는 목록은 컴포넌트 테스트로 진입 ID/차단/만료를 검증했다.
- 본문 하단으로 직접 스와이프하는 추가 검증은 CUA `drag`가 `noWindowsAvailable`로 실패해 수행하지 못했다. 휠 스크롤도 시뮬레이터 콘텐츠를 이동시키지 않았다. Android 실기기 검증은 이번 범위에서 실행하지 않았다.

## 자동 검사

확인 로그는 `/tmp/community-followup-tests.log`, `/tmp/community-story-card-tests.log`, `/tmp/community-followup-types.log`, `/tmp/community-followup-lint.log`, `/tmp/community-followup-copy.log`에 있다. 기존 35개 관련 스위트 771개 통과 후 새 스토리 컴포넌트 4개 테스트를 추가했다. 사진 카드 형태로 조정한 뒤 영향받는 4개 스위트 110개가 다시 통과했다. 총 고유 테스트 775개 통과. 타입 검사 오류 0. 댓글 화면·스토리 레일·테스트의 린트 경고 0. 추가로 수정한 기존 스토리 작성 라우트에는 이번 수정과 무관한 기존 훅 의존성/색상 리터럴 경고 10개가 있어 `--max-warnings 0`은 통과하지 않았다. X 수정 부위에는 경고가 없다. 카피 감사는 종료 코드 0이며 변경한 스토리 카피에는 발견 항목이 없다. 저장소 전역에는 기존 S1/S2 항목이 남아 있다.

## 스토리 작성 X 버튼 후속 수정

추가 사용자 보고: 빈 스토리 작성 화면의 X를 눌러도 닫히지 않는다.

원인: 뒤에 렌더되는 절대 위치 제목이 `left: 0 / right: 0`으로 X 위까지 펼쳐져 터치를 가로챈다. 제목을 좌우 80pt 안쪽으로 제한하고 `pointerEvents="none"`을 적용했다. X에는 공통 `HeaderIconButton`의 44pt 터치 영역을 적용했다. 확인 모달과 초안 보존 로직은 바꾸지 않았다.

시뮬레이터에서 기존 빈 작성 화면 및 재진입한 빈 작성 화면의 X를 각각 한 번씩 눌러 커뮤니티 복귀를 확인했다. 새 빈 스토리 카드의 진입도 확인했다.

## 사진 올리기 진입 영역 단순화

추가 피드백으로 큰 빈 상태 배너를 다시 정리했다. 상단 `올리기`와 장식 사진 묶음을 없애고, 목록의 첫 104×144 세로 카드에 `사진 올리기`를 통합했다. 빈 상태에는 오른쪽에 짧은 안내, 데이터가 있으면 실제 사진 카드가 이어진다. 빈 상태/로딩/실패에서도 생성 진입점을 유지한다. 기본 글자 크기에서 섹션 높이는 약 28pt 줄었다. 빈 상태 노출 계측, 재시도, 차단·만료 필터는 유지했다.

기존 iPhone 17 Pro 테스트 세션에서 실제 빈 상태 배치, 새 생성 카드 진입, X로 커뮤니티 복귀를 확인했다. 관련 4개 스위트 110개 테스트, 타입 검사, 변경 파일 린트(경고 0) 통과. 카피 감사 종료 코드 0, 변경한 스토리 카피에 발견 항목 없음. 로그: `/tmp/story-entry-polish-{tests,types,lint,copy}.log`.
