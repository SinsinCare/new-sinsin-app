# 지도 검색과 지역 필터 실사용 점검 — 2026-09-08

이번 범위는 지도 검색의 목적지 유지, 자동완성 갱신, 지역 필터 이동이다. 전체 페이지 점검이 끝났다는 의미는 아니다.

## 변경

- 최근 검색은 문자열 대신 종류와 목적지를 함께 보관한다. 지역은 원래 좌표로 이동하고 식당은 원래 상세 ID로 열린다. 기존 문자열 이력은 일반 검색으로 유지한다.
- 저장소를 읽기 전에 선택하거나 화면을 나가도 기존 이력에 변경을 합쳐 저장한다. 비동기 쓰기 순서를 지켜 삭제가 이전 쓰기로 되돌려지지 않게 했다.
- 입력값과 디바운스된 검색어가 다르면 이전 검색의 자동완성을 노출하지 않는다. 이전 요청의 늦은 성공·오류도 새 입력에 노출하지 않는다.
- 최근 항목 열기와 삭제를 형제 버튼으로 분리했다. X에는 최소 터치 영역을 주고 iOS 접근성 트리에서도 별도 삭제 버튼으로 인식되게 했다.
- AI와 수동 지역 필터에 같은 목적지 계산을 적용한다. 시도 전체 키를 정규화하고 세부 지역을 우선하며, 같은 선택의 순서만 바뀌면 지도를 되돌리지 않는다.
- 지역을 직접 선택하면 내 위치 자동 이동의 소유 상태를 갱신한다. 늦은 GPS가 선택한 목적지를 덮거나 탭 재선택이 잘못된 위치 상태를 읽지 않게 했다.
- 확대 안내를 “지도에는 일부 식당만 표시돼요. 확대해 보세요.”로 변경했다. 서버의 places 모드는 겹치는 격자의 대표 마커를 보내므로 결과가 4곳이어도 truncated일 수 있다. 목록의 누락이라는 뜻이 아니다. 영문도 같은 의미로 수정했다.

## 실행 환경

- 기존 로컬 API 8100과 기존 로컬 DB를 사용했다. 데이터 초기화·시드 추가·운영 데이터 수정은 하지 않았다.
- Metro가 IPv6 localhost에만 열려 iOS 개발 앱의 127.0.0.1 접속이 실패했다. 같은 8085 서버를 IPv4 우선으로 시작해 앱 연결을 복구했다.
- iPhone 17 Pro / iOS 26.5 Simulator, 한국어 라이트 모드에서 CUA로 직접 조작했다. 지도는 실제 Kakao WebView, 검색·목록은 현재 로컬 API 응답이다. 표시 메뉴·리뷰의 사실성은 이 검증에 포함하지 않는다.

## Simulator에서 직접 확인한 흐름

1. 11:21–11:23: 강남 지역 제안 → 강남 지도(334곳) → 서초 지역 제안 → 서초 지도(6곳) → 최근 강남 선택 → 강남 지도와 334곳 복원. 식당명 결과 목록으로 이동하지 않았다.
2. 11:24–11:26: 강남불백 강남1호점 자동완성 → 해당 상세 → 뒤로 → 입력 지우기 → 최근 식당 선택 → 동일 상세 재진입. 기존 문자열 이력도 함께 남아 있었다.
3. 11:28: AI 검색에 “서초 한식 식당” 입력 → 서초·한식 해석 확인 → 조건 적용 → 서초 지도 중심, 지역 1·음식 종류 1, 결과 4곳 확인.
4. 11:29–11:30: 수동 필터에서 기존 서초에 강남을 추가하고 닫기 → 지역 1과 기존 4곳 유지 → 재진입 시 강남 미선택·서초 선택 확인.
5. 11:33–11:34: 접근성 트리에 식당 열기와 삭제가 별도 버튼으로 노출됨을 확인. 테스트로 추가한 강남불백 항목의 삭제를 눌러도 검색 화면이 유지됐다. 화면을 나갔다 재진입해 삭제가 유지되는 것도 확인했다. 테스트용 서초 최근 항목도 삭제했다. 기존 강남·오레노라멘 이력은 남겼다.
6. 11:36: 강남 지도에서 수동 지역 필터의 서초 선택 → 식당 보기 → 서초구청·양재역이 보이는 지도 중심과 결과 4곳 확인. 새 확대 안내도 화면에서 확인했다.

## 자동 검사

- 지역 이동, 최근 목적지·저장소 수명주기·디바운스, 필터 초안/확정: 3 suites / 54 tests 통과.
- 검색 leaf 실행 검사 2개를 root에서 재실행: 회귀 검사 및 ESLint/Prettier 통과.
- 마지막 검색 버튼 분리 후 전체 `npx tsc --noEmit --pretty false` exit 0. 지도·검색 변경 경로 ESLint/Prettier와 `git diff --check` 통과.
- UX copy audit exit 0. 기존 후보 14개 중 이번 지도 문구에 해당하는 항목은 없었다.
- 추가 실행한 전역 탭 라우트 검사에서는 기존 `src/features/recipe/views/PostDetailScreen.tsx:531`의 `router.push({ pathname: "/community" ... })` 1건이 실패했다. 이번 수정 경로가 아니며 변경하지 않았다. 같은 스위트의 식당 지역 `dismissTo`/재선택 검사는 통과했다. 따라서 전체 저장소 회귀 검사가 모두 통과했다고 주장하지 않는다.

## 남은 확인 범위

- Android·실기기·다크 모드·큰 글씨·실제 GPS 지연은 이번 Simulator 확인 범위 밖이다. GPS 소유 상태 보완은 코드 경로 검토로 확인했다.
- 250ms 이내의 이전 자동완성 선택 방지는 훅 회귀로 검증했으며, 프레임 단위 영상 계측은 하지 않았다.
- 지역 이동 중 새 필터와 이전 bbox가 잠깐 함께 조회될 가능성은 남아 있다. 최종 목적지/결과 복원은 확인했지만 플리커 제거 완료라고 주장하지 않는다. 단순 enabled 잠금은 같은 중심으로 이동할 때 idle이 발생하지 않아 영구 잠금될 위험이 있어 추가하지 않았다.
- 이번 검색 버튼·지역 필터 점검만으로 지도 제스처·모든 상세 액션·전체 페이지의 기능 검증이 끝난 것은 아니다.
