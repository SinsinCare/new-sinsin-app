# AI 검색과 식당 카드 진입 검증 — 2026-09-08

전체 페이지를 직접 사용하며 개선하는 목표의 진행 기록이다. 이번 범위는 지도 AI 검색의 요청 수명과 목록 카드의 사진·메뉴 연결이다. 전체 앱 완료를 뜻하지 않는다.

## 재현과 수정

- AI 검색 완료 후 입력을 `서초 한식 식당`에서 `강남 중식`으로 고쳐도 이전 결과와 적용 버튼이 남았다. 요청을 입력에 묶고, 수정·지우기·닫기·언마운트 시 취소하며 늦은 성공/실패는 무시하도록 변경했다. 다시 요청하는 동안 이전 적용 결과도 제거한다.
- `식당`이 미반영 조건으로 표시됐다. 모델과 키워드 폴백의 결과 정리에서 일반 표현 전체만 제외한다. `반려견 동반`, `국물 없는 식당` 같은 실제 미지원 조건은 보존한다. 일반 명사를 메뉴 검색어로 쓰는 경로도 차단했고 정책 캐시 버전을 올렸다.
- 목록의 두 번째 사진과 대표메뉴가 모두 식당 홈으로 갔다. 사진에는 표시된 배열과 선택 순번을 전달하고, 대표메뉴에는 메뉴 탭 진입 의도를 전달한다. 지도·검색 목록·저장 목록의 공통 카드에 연결했다.
- 사진/메뉴를 열 때 지도 확대·선택 변경을 실행하지 않는다. 일반 상호명 진입의 기존 지도 처리와는 별도 동작이다.
- 메뉴 직접 진입은 실제 콘텐츠 높이를 확인한 후 탭 위치로 이동한다. 같은 식당을 홈 또는 메뉴로 열 때 초기 상태가 섞이지 않도록 인스턴스 키에 진입 탭을 반영했다.
- 검색 목록의 뒤로가기가 부모 검색 버튼에 묶여 접근성 트리에서 사라졌다. 독립된 두 버튼으로 분리하고 뒤로가기의 44pt 영역을 확보했다. 글자 크기를 확대하지 않았다.

## 실제 실행 근거

환경: iPhone 17 Pro / iOS 26.5 / 한국어 / 라이트, 실행 중인 로컬 API 8100와 Metro 8085. CUA로 앱을 조작했다.

1. AI `서초 한식 식당` 결과에서 서초·한식 조건이 표시되고 `식당` 미반영 안내가 없어졌다.
2. 입력을 `강남 중식`으로 편집하자 이전 설명·조건·적용 버튼이 즉시 사라졌다. 다시 검색한 결과는 강남·중식이었다.
3. 적용하지 않고 닫은 뒤 재진입하면 입력과 결과가 비어 있었다. 취소 후 기존 지도 필터가 유지됐다.
4. `서초 한식 반려견 동반 식당` 결과는 미지원 조건 `반려견 동반`을 유지하고 `식당`은 제외했다.
5. 지도 목록의 크라이치즈버거 강남점 두 번째 사진 → 사진 뷰어 `2 / 3` → 뒤로: 기존 32곳 결과와 선택 카드가 유지됐다.
6. 지도 대표메뉴 → 메뉴 탭 선택 상태로 바로 진입. 스크린샷에서 상호명 헤더 바로 아래 탭과 메뉴 목록이 보였다. 처음 연 오늘도등심 강남점에서도 같은 위치로 진입했다. 두 식당 모두 뒤로가기로 같은 지도 목록에 복귀했다.
7. 메뉴 자동완성 `파스타` → 별도 검색 결과 목록 → 두 번째 사진 `2 / 3` → 복귀. 대표메뉴 → 메뉴 탭 → 복귀까지 확인했다. 검색어와 목록이 유지됐다.
8. 검색 목록 접근성 트리에 `뒤로`와 `검색 조건 바꾸기`가 각각 노출됐다. 뒤로를 눌러 파스타 검색 화면에 돌아왔고, 한 번 더 뒤로를 눌러 기존 지도 32곳 상태에 복귀했다.

## 자동 검증

`AI-SEARCH-GATES.md`의 A1–A3를 최종 코드에서 다시 실행했다. 각 명령 exit 0 및 EXPECT 일치.

- 프론트엔드: AI 요청 수명, 응답 가드, 카드 목적지, 상세 인스턴스 초기화, 사진 순서 필터, 목록 레이아웃 관련 6개 스위트.
- 백엔드: 실제 결과 파서와 키워드 폴백을 사용하는 4개 순수 함수 테스트 통과. 테스트 preload가 로컬 테스트 DB 연결 불가 경고를 출력했다. DB 연동 검증으로 간주하지 않았으며 보호 장치를 변경하지 않았다.
- 프론트엔드 및 백엔드 TypeScript, 변경 프론트엔드 경로 ESLint/Prettier, 두 저장소 `git diff --check` 통과.
- 명령·실행 위치·결과는 게이트 파일, 실행 요약은 `/tmp/map-ai-gate-final.log`.

## 검증 한계와 다음 범위

- 늦은 응답·늦은 실패·닫기 중 요청 취소·연속 탭은 지연 Promise 기반 회귀 테스트로 검증했다. 실제 네트워크를 의도적으로 지연시킨 Simulator 검증은 하지 않았다.
- 저장 목록에도 같은 카드 대상이 전달되는 코드와 목적지 함수를 확인했지만, 이번 실제 세션에서 저장 목록의 사진/메뉴 진입까지 완료하지 못했다. 목록 하단 이동 도중 CUA 스크롤이 `noWindowsAvailable`, 캡처가 `ScreenCaptureKit -3811`로 간헐 실패했다. 사진·메뉴의 실제 동작 근거는 지도와 검색 결과 목록이다.
- 실제 손가락 제스처, Android, 작은 기기, 큰 글씨 및 다크 모드는 이번 변경 후 별도로 검증하지 않았다.
- 저장·후기 게시·전화 발신·외부 공유를 실행하거나 기존 사용자 데이터를 변경하지 않았다. 기존 개발용 대표메뉴 이름을 다른 메뉴로 지어내지 않았다.
- 저장 목록, 상세의 외부 앱 연결·공유·후기, 그 뒤 나머지 페이지의 사용 검증은 전체 목표의 후속 범위로 남아 있다.
